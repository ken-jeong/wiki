> [1. 서비스 기획 개념 학습](https://pangmoo.notion.site/1-363f0f083884802588a9dd69c2e74a42)

## 1. Intro — PM이란?
- ChatGPT의 정의에 따르면, **PM(Product Manager)은 프로덕트의 개발과 성공을 책임지는 사람**이다.
	- 고객 니즈 파악, 제품 방향·비전·전략 설정, 그리고 엔지니어링·디자인·세일즈·마케팅 등
	- cross-functional 팀과의 협업을 통해 제품을 시장에 출시하는 것까지 모두 포함된다.

- 주요 책임은
	- 마켓 리서치, 로드맵·기능 우선순위 설정, 개발팀과의 협업, 가치 제안 전달, 데이터 분석 기반 의사결정, 예산·리소스 관리 등이다.

## 2. PM vs 서비스 기획자
- 한국에서는 두 명칭이 혼용되어 왔다.
	- 1990~2000년대: "서비스 기획자" (네이버, 다음 등 포털 중심)
	- 2010년대~: 실리콘밸리 영향으로 "PM" 개념 도입
	- 2020년대~: 병행 사용, 최근엔 PM으로 통일하는 추세 (예: 우아한형제들)

**핵심 차이**:

|구분|PM|서비스 기획자|
|---|---|---|
|집중 영역|프로덕트 방향성·전략, 비즈니스+사용자 균형|사용자 경험·서비스 설계|
|전략 기여|적극적, 수립 주체|제한적|
|실행 역할|주체 아님, 과정에 적극 관여|실행 주체, 관리는 제한적|
|적합 조직|목적조직 (쿠팡, 토스, 우아한형제들, 당근)|기능조직 (카카오, 네이버)|

- **결론**
	- **직무 이름이 아니라 JD(역할)을 봐야 한다.**
	- 이름이 PM이어도 실제로는 기획자일 수 있고 그 반대도 마찬가지이다.

- **PO(Product Owner)**
	- 토스의 정의에 따르면 PO는 0→1(혁신 탄생), PM은 1→100(안정성·효율 개선) 역할로 구분된다.

## 3. 프로덕트 매니저 vs 프로젝트 매니저
- **프로젝트 매니저**
	- 일의 **'과정'**을 관리
	- 진행 중인 프로젝트의 일정·리소스를 챙김
	- PMO 조직에서 자주 활약

- **프로덕트 매니저**
	- 일의 **'내용'과 '방식'**을 관리
	- 전략 수립과 실행 모두에 적극 기여

## 4. PM의 4가지 유형
- 전문성에 따라 나뉜다.
	- **코어 PM**: 기능 업무로 고객 페인포인트 해결
	- **그로스 PM**: 비즈니스 지표 향상 관점
	- **플랫폼 PM**: 비즈니스 스케일링 담당
	- **혁신 PM**: 신규 기회 발굴, PMF 확장

- 다른 분류로 5가지
	- 제너럴리스트 / 뉴벤처 / 플랫폼 / 도메인 지식 / 성장 중심 PM

## 5. PM의 역할
- 본질적으로 두 가지이다.
	- **① 전략 수립**: 시장·사용자 분석 → 프로덕트 전략 → 비전 달성 로드맵
	- **② 실행**: 이해관계자와 협업 → 프로젝트 관리 → 세부 과제 기획

> **PM = 전략적 사고 + 실행력으로 프로덕트를 성장시키는 사람**
> 이를 통해 사용자 가치 제공과 비즈니스 목표 달성을 동시에 이뤄낸다.

## 6. IT 서비스 기획이란?
- 개념을 단계별로 풀면 이렇다.
	- **서비스** = 고객 니즈를 해결하기 위해 제공되는 상품·노역
	- **IT** = 컴퓨터로 데이터·정보를 다루는 기술
	- **IT 서비스** = IT/SW 기술로 현실 고객의 어려움을 해결하는 일
	- **IT 서비스 기획** = 아이디어를 도출해 하나의 서비스·제품으로 구체화하는 전 과정

- 기획의 일반적 프로세스
	- 문제 정의 → 요구사항 정의 → 기획 정책 수립 → 기능 정의
	- → IA/순서도 작성 → W.F. 작성 → 화면 설계서 작성 → 서비스 운영 정책서/매뉴얼 수립
