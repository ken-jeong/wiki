> [3. IA와 User Flow 개념 이해와 Figma/FigJam을 활용한 IA와 User Flow 설계](https://pangmoo.notion.site/3-IA-User-Flow-Figma-FigJam-IA-User-Flow-36bf0f08388480329f01f83a5314e06e)

## 요약
- IA는 서비스의 지도를 그리는 것이다.
- User Flow는 그 지도 위에서 사용자가 걷는 길을 그리는 것이다.
- 화면 설계에 들어가기 전 반드시 이 두 가지로 구조와 흐름을 먼저 정리해야 한다.

## 1. 핵심 개념
- **User Flow (사용자 흐름)**
	- 사용자가 특정 목적을 달성하기 위해 거치는 화면과 행동의 흐름도
	- 서비스의 "이동 경로" 역할
	- 도형, 화살표, 플로우차트로 표현

- **IA (Information Architecture, 정보 구조도)**
	- 서비스 안의 정보, 메뉴, 기능, 화면을 사용자가 이해하기 쉽게 구조화한 것
	- 서비스의 "뼈대" 또는 "지도" 역할
	- 표, 트리 구조, 사이트맵으로 표현

- **둘의 차이**
	- User Flow는 "목표 달성을 위해 어떤 경로를 거치는가?"에 답한다.
	- IA는 "어떤 화면이 있는가?"에 답한다.

### 1.1. User Flow 작성 방법
- 작성 순서
	- 사용자 목표 → 시작 화면 → 행동 나열 → 화면 연결
	- → 조건 분기 → 예외 상황 → 최종 도착 화면

- **표현 도형**
	- 사각형: 화면
	- 마름모: 조건·분기
	- 화살표: 이동
	- 둥근 사각형: 시작·종료
	- 메모: 설명

- **4가지 흐름 유형**
	- 정상 흐름 (목표 달성)
	- 예외 흐름 (조건에 따른 다른 경로)
	- 오류 흐름 (에러·실패)
	- 이탈 흐름 (중간 이탈)

### 1.2. IA 작성 방법
- 작성 순서
	- 핵심 기능 정리 → 기능 그룹핑
	- → 상위 메뉴 정하기 → 하위 화면 정리
	- → Screen ID 부여 → 누락 화면 확인

- **주요 용어**
	- Depth: 메뉴의 단계 (1Depth는 최상위, 2·3Depth는 하위)
	- GNB: 웹사이트 상단 메뉴
	- LNB: 좌측 하위 메뉴
	- Tab Bar: 모바일 하단 메뉴
	- Screen ID: 화면을 구분하는 고유 ID
		- (예: `PLAN_HOME_001` - 서비스약어_메뉴약어_번호)

- **좋은 IA의 조건**
	- 직관적인 메뉴명,
	- 자연스러운 상하위 관계,
	- 비슷한 기능끼리 그룹화,
	- 누락·중복 최소화

## 2. Figma vs FigJam
|     도구     |                  용도                   |
| :--------: | :-----------------------------------: |
| **FigJam** | 아이디어 정리, IA·User Flow, 브레인스토밍 (화이트보드) |
| **Figma**  |    UI 디자인, 와이어프레임, 화면 설계서 (정교한 제작)    |

- 작업 순서: FigJam에서 구조·흐름 정리 → Figma에서 실제 화면 설계로 연결

## 3. ChatGPT 활용
- IA·User Flow 초안을 빠르게 만들 수 있지만, **그대로 쓰지 말고 서비스 목적에 맞게 수정** 필요
- 프롬프트에는 서비스 아이디어, 핵심 기능, 사용자 목표, 조건 분기 요구사항을 명시한다.

## 4. 실습 & 과제
- **실습 4단계**
	- 핵심 기능 정리
	- → IA 표 작성
	- → User Flow 작성
	- → FigJam 시각화

- **3주차 과제**
	- 서비스 아이디어
	- 핵심 기능 목록
	- IA(구조도+표)
	- User Flow
