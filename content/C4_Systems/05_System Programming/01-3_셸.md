> **학습 목표**: 셸이 명령줄을 읽고, 명령과 인수를 분리한 뒤, 자식 프로세스에서 프로그램을 실행하는 흐름을 설명할 수 있다.

## 1. 먼저 기억할 핵심
**셸은 명령어를 해석하고 실행을 관리하는 프로그램이다.**
외부 명령을 실행할 때는 보통 자식 프로세스를 만들고, 그 자식이 실행할 프로그램으로 자신의 내용을 바꾼다.

```text
명령줄 입력
    ↓
토큰 분리 → 명령어와 인수 배열 구성
    ↓
fork(): 자식 프로세스 생성
    ├─ 자식: execvp() → 외부 프로그램 실행 → 종료
    └─ 부모(셸)
         ├─ 포그라운드: waitpid() → 자식 종료 회수 → 다음 명령
         └─ 백그라운드: 즉시 다음 명령 처리
```

| 핵심 요소 | 역할 | 기억할 점 |
|---|---|---|
| 셸 | 명령을 해석하고 실행을 관리 | 부모 프로세스로 남아 다음 명령을 받음 |
| `fork()` | 자식 프로세스 생성 | 부모와 자식이 반환값으로 실행 경로를 구분 |
| `execvp()` | 현재 프로세스에서 다른 프로그램 실행 | 성공하면 기존 코드로 돌아오지 않음 |
| `waitpid()` | 특정 자식의 종료를 기다리고 상태 회수 | 이 예제에서는 포그라운드 명령에 사용 |
| `&` | 앞 명령을 백그라운드로 실행 | 셸이 해당 명령의 종료를 즉시 기다리지 않음 |
| `;` | 명령 구분 | 앞 명령을 처리한 뒤 다음 명령을 파싱 |

## 2. 셸이 하는 일
### 2.1. 명령어 해석기
셸은 입력된 명령을 해석하고 실행한다.

일반적인 셸 기능은 다음과 같다.
- 외부 명령을 자식 태스크에서 실행
- 내부 명령 처리
- 파이프, 입출력 재지정(redirection), 백그라운드 실행 처리
- 복잡한 명령을 위해 여러 태스크 생성
- 셸 스크립트 처리

**주의**
- 위 목록은 일반적인 셸의 기능이다.
- 뒤에 나오는 `smallsh` 예제에 이 기능이 모두 구현되어 있는 것은 아니다.

### 2.2. 내부 명령과 외부 명령
| 구분    | 처리 방식         | 자료의 예                         |
| ----- | ------------- | ----------------------------- |
| 내부 명령 | 셸 자체 코드가 처리   | `main.c`에서 문자열이 `exit`이면 셸 종료 |
| 외부 명령 | 자식에서 실행 파일 실행 | `ls`, `ps`, `./hello` 실행      |

**보충**
- `cd`처럼 셸 자체의 상태를 바꿔야 하는 명령은 셸 프로세스에서 처리해야 한다.
- 자식에서만 작업 디렉터리를 변경하면 부모 셸의 작업 디렉터리는 바뀌지 않는다.

### 2.3 기본 동작과 실행 화면
일반적인 반복 구조는 다음과 같다.

1. 프롬프트를 출력한다.
2. 명령줄을 읽는다.
3. 명령을 토큰 단위로 나눈다.
4. 내부 명령이면 직접 처리한다.
5. 외부 명령이면 실행 처리를 호출한다.
6. 다음 명령을 받기 위해 반복한다.

## 3. 부모와 자식의 실행 흐름
### 3.1. `fork()`로 실행 경로 나누기
`fork()`를 호출하면 반환값에 따라 부모와 자식이 다른 코드를 실행한다.

| 반환값 | 의미 | 예제의 처리 |
|---|---|---|
| `-1` | 생성 실패 | 오류 출력 후 `-1` 반환 |
| `0` | 자식에서 받은 반환값 | `execvp()` 호출 |
| 양수 | 부모에서 받은 자식 PID | 백그라운드 여부에 따라 대기 결정 |

### 3.2. `execvp()`로 프로그램 바꾸기
```c
execvp(*cline, cline);
```
- `cline`은 명령어와 인수 문자열의 포인터 배열이다.
- `*cline`은 `cline[0]`과 같으며, 실행할 명령어를 가리킨다.
- 배열의 마지막에는 `NULL`이 들어가야 한다.

**보충**
- `execvp()`는 새 프로세스를 만드는 함수가 아니다.
- 호출한 프로세스의 프로그램 이미지를 새 프로그램으로 교체한다.
- `v`는 인수 배열을 받는 형태, `p`는 필요한 경우 `PATH`에서 실행 파일을 찾는 형태라는 점으로 기억하면 좋다.

```text
fork()   = 자식 생성
execvp() = 그 자식이 실행할 프로그램으로 교체
```

### 3.3. `waitpid()`와 좀비 프로세스
```c
waitpid(pid, &status, 0);
```

부모 셸은 지정한 `pid`의 자식이 종료할 때까지 기다리고 종료 상태를 회수한다.

63쪽 그림은 자식이 `execve`로 프로그램을 실행하고 `exit`한 뒤, 부모가 `wait`로 종료를 회수하는 흐름을 보여 준다.
실제 `smallsh` 코드에서는 `execvp`와 `waitpid`를 사용한다.

**보충**
- 자식이 종료했지만 부모가 아직 종료 상태를 회수하지 않은 상태를 좀비라고 한다.
- `wait` 계열 함수는 대기뿐 아니라 종료한 자식의 상태를 회수하는 역할도 한다.
- 부모가 먼저 대기 중일 수도 있으므로 그림의 화살표를 고정된 호출 순서로 이해하지 않도록 한다.

## 4. smallsh 전체 구조
```text
main()
  ├─ userin(prompt)         입력 한 줄 읽기
  └─ procline()             입력줄을 명령 단위로 처리
       ├─ gettok()          토큰 하나 추출
       │    └─ inarg()      일반 인수에 속하는 문자 판별
       └─ runcommand()      자식 생성 및 명령 실행
```
`main()`은 `userin()`으로 입력을 받은 뒤, 입력이 `EOF`가 아니면 `procline()`을 호출한다.

```c
char *prompt = "Command> ";

main() {
	while (userin(prompt) != EOF) {
		procline();
	}
}
```

| 함수 | 담당하는 질문 |
|---|---|
| `main()` | 입력과 실행을 언제까지 반복할까? |
| `userin()` | 입력 한 줄을 어떻게 저장할까? |
| `gettok()` | 다음 토큰은 무엇이며 어떤 종류일까? |
| `inarg()` | 이 문자를 현재 인수에 계속 붙일까? |
| `procline()` | 인수를 모아 언제 명령 하나를 실행할까? |
| `runcommand()` | 어느 프로세스에서 실행하고 부모는 기다릴까? |

### 4.1. 주요 상수
```c
#define EOL          1  // 줄 끝 토큰
#define ARG          2  // 일반 명령어 또는 인수 토큰
#define AMPERSAND    3  // & 토큰
#define SEMICOLON    4  // ; 토큰

#define MAXARG     512  // 명령어를 포함해 수집할 인수 항목 수의 한도
#define MAXBUF     512  // 입력 버퍼 크기

#define FOREGROUND   0  // 부모가 기다리는 실행 방식
#define BACKGROUND   1  // 부모가 즉시 기다리지 않는 실행 방식
```

`MAXBUF` 크기 전체를 일반 문자로 채울 수 있는 것은 아니다.
줄 끝 문자와 문자열 종료 문자 `\0`를 저장할 공간도 고려해야 한다.

## 5. 입력과 토큰 처리
### 5.1. `userin()`: 입력 한 줄 저장
| 변수                   | 역할              |
| -------------------- | --------------- |
| `inpbuf[MAXBUF]`     | 원본 입력줄 저장       |
| `tokbuf[2 * MAXBUF]` | 분리한 토큰 문자열 저장   |
| `ptr`                | 입력 버퍼를 읽는 위치    |
| `tok`                | 토큰 버퍼에 쓰는 위치    |
| `count`              | 입력 버퍼에 저장한 문자 수 |

동작 순서:
1. `ptr`과 `tok`를 각 버퍼의 시작으로 되돌린다.
2. 프롬프트 `Command> `를 출력한다.
3. `getchar()`로 문자를 읽어 입력 버퍼에 저장한다.
4. 정상적으로 개행을 읽으면 뒤에 `\0`를 붙이고 문자 수를 반환한다.
5. 입력줄이 너무 길면 개행까지 읽은 후 오류를 출력하고 다시 입력받는다.
6. `EOF`이면 `EOF`를 반환해 메인 반복문을 끝낸다.

#### 예제
```c
static char inpbuf[MAXBUF], tokbuf[2*MAXBUF], *ptr = inpbuf, *tok = tokbuf;

int userin(char *p) {
	int c, count;
	ptr = inpbuf;  tok = tokbuf;  // 뒤의 루틴들을 위한 초기화
	printf("%s", p);
	
	while (1) {
		if ((c = getchar()) == EOF) {
			return (EOF);
		}
		if (count < MAXBUF) {
			inpbuf[count++] = c;
		}
		if (c == '\n' && count < MAXBUF) {
			inpbuf[count] = '\0';
			return count;
		}
		if (c == '\n') {  // 줄이 너무 길면 재시작
			printf("smallsh: input line too long\n");
			count = 0;
			printf("%s", p);
		}
	}
}
```

### 5.2. `gettok()`: 토큰 하나 추출
토큰은 명령줄을 해석하기 위한 작은 단위다.
이 예제는 공백과 탭을 건너뛰고, 다음 문자를 기준으로 토큰을 분류한다.

| 입력 내용 | 반환하는 토큰 종류 |
|---|---|
| 명령어 또는 인수 문자열 | `ARG` |
| 개행 `\n` | `EOL` |
| `&` | `AMPERSAND` |
| `;` | `SEMICOLON` |

**보충 예시**:
```text
입력: ls -l; sleep 3 &\n

"ls"   → ARG
"-l"   → ARG
";"    → SEMICOLON
"sleep"→ ARG
"3"    → ARG
"&"    → AMPERSAND
"\n"   → EOL
```

일반 문자열은 `inarg()`가 참인 동안 계속 복사하고, 각 토큰 뒤에 `\0`를 붙인다. `gettok(char **outptr)`는 이중 포인터를 통해 호출자의 인수 포인터에 토큰의 시작 주소를 저장한다.

#### 예제
```c
int gettok(char **outptr) {
    int type;
    *outptr = tok;
    while (*ptr == ' ' || *ptr == '\t') ptr++;  // 여백 제거
    *tok++ = *ptr;

    switch (*ptr++) {
    case '\n': type = EOL;       break;
    case '&':  type = AMPERSAND; break;
    case ';':  type = SEMICOLON; break;
    default:
        type = ARG;
        while (inarg(*ptr)) *tok++ = *ptr++;  // 보통문자를 계속 읽는다.
    }
    *tok++ = '\0';
    return type;
}
```

### 5.3. `inarg()`: 인수가 끝나는 위치 판별
다음 문자들을 일반 인수의 경계로 사용한다.
```text
공백, 탭, &, ;, 개행
```

**주의**
- 원본 코드의 `special[]`에는 `\0`도 있지만, 반복문은 배열에서 `\0`를 만나는 즉시 끝난다.
- 따라서 현재 구현은 입력 문자 `c`가 `\0`일 때 이를 직접 경계로 판별하지 못한다. 안전하게 구현하려면 `c == '\0'`도 별도로 처리해야 한다.

#### 예제
```c
static char special[] = {' ', '\t', '&', ';', '\n', '\0'};

int inarg(char c) {
	char *wrk;
	for (wrk = special; *wrk; wrk++) {
		if (c == *wrk) { 
			return (0);
		}
	}
	return (1);
}
```

## 6. `procline()`: 인수를 모으고 명령 실행
`procline()`은 `gettok()`를 반복 호출해 명령어와 인수를 `arg` 배열에 모은다.

```c
char *arg[MAXARG + 1];
```

마지막 `+1`은 인수 배열 끝의 `NULL`을 위한 공간이다.

| 받은 토큰 | 처리 |
|---|---|
| `ARG` | 인수 개수 `narg` 증가 |
| `AMPERSAND` | 현재 명령을 `BACKGROUND`로 실행 |
| `SEMICOLON` | 현재 명령을 `FOREGROUND`로 실행하고 다음 명령 처리 |
| `EOL` | 현재 명령을 `FOREGROUND`로 실행하고 입력줄 처리 종료 |

명령을 실행하기 직전에 다음을 수행한다.

```c
arg[narg] = NULL;
runcommand(arg, type);
```

- `narg != 0`일 때만 실행하므로 빈 명령은 실행하지 않는다.
- 명령 하나를 실행한 후에는 `narg = 0`으로 초기화한다.
- `EOL`이면 함수에서 반환한다.
- `;`나 `&`이면 같은 입력줄의 다음 토큰을 계속 읽는다.

**보충 예시**: `ls -l`은 다음처럼 전달된다.

```text
arg[0] → "ls"
arg[1] → "-l"
arg[2] → NULL
```

문자열 끝의 `\0`와 배열 끝의 `NULL`은 다르다.
`\0`는 문자 하나로 문자열을 끝내고, `NULL`은 포인터 배열을 끝낸다.

#### 예제
```c
int procline(void) {
	char *arg[MAXARG + 1];  // runcommand를 위한 포인터 배열
	int  toktype;           // 명령 내 토큰의 유형
	int  narg = 0;          // 지금까지의 인수 수
	int  type;              // FOREGROUND 또는 BACKGROUND
	
	for (;;) {
		switch (toktype = gettok(&arg[narg])) {
		case ARG:
			if (narg < MAXARG) narg++;
			break;
		case EOL:
		case SEMICOLON:
		case AMPERSAND:
			type = (toktype == AMPERSAND) ? BACKGROUND : FOREGROUND;
			if (narg != 0) {
				arg[narg] = NULL;
				runcommand(arg, type);
			}
			if (toktype == EOL) return;
			narg = 0;
			break;
		}
	}
}
```

## 7. `runcommand()`: 실제 프로세스 실행
핵심 코드를 학습용으로 정돈하면 다음과 같다.
전체 셸 프로그램이 아니라 실행 흐름을 보여 주는 발췌다.

```c
pid = fork();

if (pid == -1) {
    perror("smallsh");
    return -1;
}

if (pid == 0) {  // 자식
    execvp(cline[0], cline);
    perror(cline[0]);  // execvp 실패 시에만 실행
    exit(1);
}

// 부모 셸
if (where == BACKGROUND) {
    printf("[Process id %d]\n", pid);
    return 0;
}

if (waitpid(pid, &status, 0) == -1)
    return -1;

return status;
```

### 8.1. 포그라운드와 백그라운드 비교
| 항목       | 포그라운드          | 백그라운드                |
| -------- | -------------- | -------------------- |
| 보충 예시    | `sleep 3`      | `sleep 3 &`          |
| 자식의 동작   | 명령 실행          | 명령 실행                |
| 부모의 동작   | `waitpid()` 호출 | 자식 PID 출력 후 반환       |
| 다음 입력 처리 | 해당 자식 종료 후     | 해당 자식 종료를 기다리지 않고 진행 |

**핵심**
- 백그라운드 실행에서도 `fork()`와 `execvp()`는 수행한다.
- 달라지는 부분은 부모 셸이 즉시 기다리는지 여부다.

## 8. 한 줄의 명령으로 전체 흐름 연결하기
**보충 예시**:
```sh
sleep 3 & ls -l; ps
```

| 단계 | 파싱 결과 | 실행 방식 | 부모 셸의 동작 |
|---|---|---|---|
| 1 | `sleep`, `3`, `&` | 백그라운드 | 자식 PID 출력 후 다음 명령 처리 |
| 2 | `ls`, `-l`, `;` | 포그라운드 | `ls` 자식의 종료를 회수한 뒤 다음 명령 처리 |
| 3 | `ps`, 개행 | 포그라운드 | `ps` 자식의 종료를 회수한 뒤 입력줄 처리 종료 |

`sleep`은 뒤의 명령들과 동시에 진행될 수 있다.
`ls`와 `ps`는 부모 셸이 각각 기다리므로 순서대로 실행된다.
이후 셸은 새 입력을 받는다.
