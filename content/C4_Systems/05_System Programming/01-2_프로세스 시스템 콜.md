## 1. 먼저 이해할 전체 흐름
프로세스는 **실행 중인 프로그램**이다.
프로세스의 생성, 프로그램 교체, 종료, 부모의 대기를 다룬다.

```text
부모 프로세스
    |
    fork() ------------------ 자식 프로세스 생성
    |                              |
부모의 코드 계속 실행            exec 계열 함수
    |                              |
wait() / waitpid()              새로운 프로그램 실행
    |                              |
자식 종료 대기                  exit(status)
    |                              |
    +--------- 종료 상태 수집 ------+
    |
부모의 코드 계속 실행
```

| 기능 | 핵심 함수 | 기억할 문장 |
|---|---|---|
| 프로세스 생성 | `fork()` | 나를 복제한 자식을 만든다. |
| 프로그램 교체 | `exec` 계열 | 현재 프로세스에서 실행할 프로그램을 바꾼다. |
| 프로세스 종료 | `exit(status)` | 실행을 끝내고 종료 코드를 남긴다. |
| 자식 종료 대기 | `wait()`, `waitpid()` | 자식의 종료를 기다리고 상태를 수집한다. |

**가장 중요한 구별**
- `fork()`는 프로세스를 하나 더 만든다.
- `exec`는 현재 프로세스의 프로그램 이미지를 교체한다.

## 2. 사용자 모드와 시스템 모드
| 구분    | 사용자 모드(User mode)    | 시스템 모드(System mode / 커널 모드) |
| ----- | -------------------- | --------------------------- |
| 실행 내용 | 사용자가 작성한 프로그램의 일반 코드 | 시스템 호출 처리와 인터럽트 처리          |
| 관점    | 사용자 프로그램 수행          | 커널 기능 수행                    |
| 스택    | 사용자 스택               | 커널 스택                       |

- 시스템 호출을 하면 커널 모드로 들어가 필요한 처리를 수행한다.
- 한 실행 흐름이 사용자 모드와 커널 모드에서 동시에 수행되지는 않는다.
- 모드 전환은 사용자 코드에서 커널 코드로 실행 영역이 바뀌는 것이다.

> **이해 보충**
> 모드 전환 자체가 새 프로세스를 만드는 것은 아니다.
> 같은 프로세스가 시스템 호출을 통해 커널 기능을 이용할 수 있다.

## 3. `fork()`: 자식 프로세스 생성
### 3.1. 호출 한 번, 실행 흐름 두 개
```c
#include <sys/types.h>
#include <unistd.h>

pid_t fork(void);
```

`fork()`에 성공하면 부모와 자식이 **각자의 실행 흐름에서 `fork()` 다음 코드부터** 실행한다.

| 실행 주체 / 상황 | `fork()` 반환값 | 의미 |
|---|---:|---|
| 부모 | 자식의 PID인 양수 | 생성된 자식을 식별할 수 있다. |
| 자식 | `0` | 자식 분기임을 알 수 있다. |
| 생성 실패 | `-1` | 자식이 생성되지 않았다. |

```c
pid_t pid = fork();

if (pid < 0) {
    /* 생성 실패 */
} else if (pid == 0) {
    /* 자식만 실행 */
} else {
    /* 부모만 실행: pid는 자식의 PID */
}

/* 성공했다면 부모와 자식이 모두 실행 */
```

**주의**
- 자식이 받는 반환값 `0`은 자식의 실제 PID가 아니다.
- 자신의 PID는 `getpid()`, 부모의 PID는 `getppid()`로 확인한다.

### 3.2. 누가 먼저 실행될까?
**실행 순서는 보장되지 않는다.** 커널의 스케줄링에 따라 달라진다.

예제에서는 다음과 같이 실행된다.
- `fork()` 이전의 `Hello` 출력 호출: 부모가 1번 실행
- 자식 분기의 출력: 자식만 실행
- 부모 분기의 출력: 부모만 실행
- 분기 밖의 `Bye` 출력: 부모와 자식이 각각 실행하여 총 2번

슬라이드의 실행 화면은 자식의 메시지가 먼저 나온 사례이다.
**항상 같은 순서로 출력된다는 뜻은 아니다.**

> **이해 보충**
> 여러 프로세스가 함께 실행 가능한 상태가 된다는 것과, 같은 순간에 여러 CPU에서 실행된다는 것은 구별해야 한다.
> 또한 `sleep()`은 지연을 만들 뿐, 정확한 실행 순서를 보장하는 동기화 방법은 아니다.

### 3.3. 무엇을 상속하고, 무엇이 달라질까?
| 항목                           | `fork()` 이후          |
| ---------------------------- | -------------------- |
| 변수의 값                        | 부모의 값을 복제하여 시작       |
| 일반적인 데이터·스택의 변경              | 부모와 자식에서 각각 독립적으로 반영 |
| 열린 파일 디스크립터                  | 자식에게 상속              |
| 상속된 열린 파일의 현재 오프셋            | 부모와 자식이 공유           |
| 실제·유효 UID/GID, 보조 그룹 ID      | 상속                   |
| 프로세스 그룹 ID, 세션 ID, 제어 터미널    | 상속                   |
| set-user/group-ID 관련 플래그     | 강의에서 상속 항목으로 제시      |
| 현재 작업 디렉터리, 루트 디렉터리, `umask` | 상속                   |
| 시그널 마스크와 처리 설정               | 상속                   |
| close-on-exec 플래그            | 상속                   |
| 환경 변수, 자원 제한                 | 상속                   |
| PID와 PPID                    | 부모와 자식이 서로 다름        |
| 자식의 자원 사용 누적량                | 0으로 초기화              |
| 자식의 예약 알람                    | 제거                   |
| 자식의 대기 중인 시그널 집합             | 빈 집합으로 시작            |

### 3.4. 변수 복제 예제
강의의 두 번째 예제는 전역 변수 `glob = 6`, 지역 변수 `var = 88`에서 시작하고, 자식만 두 값을 증가시킨다.

```c
/* fork() 전 */
int glob = 6;  /* 전역 변수 */
/* ... */
int var = 88;  /* 지역 변수 */

/* fork() 후 자식 분기 */
glob++;
var++;
```

| 프로세스 | 최종 `glob` | 최종 `var` |
|---|---:|---:|
| 부모 | 6 | 88 |
| 자식 | 7 | 89 |

전역 변수도 자식이 수정했다고 해서 부모의 값이 바뀌지 않는다.
**같은 이름의 변수여도 별도 프로세스의 메모리이다.**

```text
fork 이전: 부모 [glob=6, var=88]

fork 이후: 부모 [glob=6, var=88]
           자식 [glob=6, var=88]

자식 수정: 부모 [glob=6, var=88]
           자식 [glob=7, var=89]
```

#### 예제
```c
/* test_fork.c: 같은 변수 접근 */
#include <sys/types.h>
#include <unistd.h>

char buf[] = "a write to stdout\n";
int  glob  = 10;

int main(void) {
	if (write(STDOUT_FILENO, buf, sizeof(buf)) != sizeof(buf)) {
		perror("write error");
		exit(1);
	}
	
	printf("pid=%d\n", getpid());
	
	pid_t pid;
	int   var = 20;
	
	if ((pid = fork()) < 0) {  // fork()의 반환값으로 분기한다.
		// 음수(-1): fork 실패
		perror("fork error");
		exit(1);
	} else if (pid == 0) {
		// 0: 자식 프로세스
		printf("child> pid=%d, ppid=%d\n", getpid(), getppid());
		glob++;
		var++; 
	} else {
		// 양수(자식 PID): 부모 프로세스
		printf("parent> child_pid=%d\n", pid);
		sleep(2);
	}
	
	printf("process> pid=%d, glob=%d, var=%d\n", getpid(), glob, var);
	/*
		# 변수의 상속
		fork 시 부모 변수 값은 자식에게 복제되어 전달된다.
		pid=자식, glob=11, var=21 | 자식이 변수 값을 바꿔도
		pid=부모, glob=10, var=20 | 부모의 변수 값은 그대로
	*/
	exit(0);
}
```

### 3.5. 표준 출력 버퍼를 주의하자
강의 예제에는 다음 두 출력이 `fork()` 앞에 있다.
```c
write(STDOUT_FILENO, buf, sizeof(buf));
printf("before fork\n");
```

**이해 보충**
- `printf()`가 아직 출력하지 않은 사용자 공간 버퍼도 `fork()` 때 복제될 수 있다.

- 터미널에서는 보통 줄바꿈으로 버퍼가 비워져 `before fork`가 한 번 보인다. 강의 화면도 이 경우이다.
- 파일로 출력을 리다이렉션하면 버퍼에 남은 문자열이 복제되어, 부모와 자식이 종료할 때 각각 출력할 수 있다.
- `write()`는 `stdio` 출력 버퍼를 거치지 않으므로 이와 같은 버퍼 복제 문제와 구별한다.
- 필요하면 `fork()` 전에 `fflush(stdout)`로 표준 출력 버퍼를 비운다.

> **예제 읽기 보충**
> 문자열 배열에 `sizeof(buf)`를 쓰면 마지막 널 문자까지 포함된다.
> 문자열의 보이는 문자만 쓰려면 이 예제에서는 `sizeof(buf) - 1`을 사용할 수 있다.

### 3.6. 프로세스 생성 모델
일반적인 프로세스 생성 모델의 선택지를 소개한다.
- 자원 공유 범위: 전체 공유 / 일부 공유 / 공유 없음
- 실행 관계: 부모와 자식이 함께 진행 / 부모가 자식 종료까지 대기

이를 `fork()`가 모든 자원을 공유한다는 뜻으로 이해하면 안 된다.
일반적인 `fork()`에서는 **메모리의 변경은 독립적이고, 상속된 열린 파일의 오프셋은 공유**된다.

### 3.7. `fork()`와 열린 파일
> 디스크립터와 오프셋 구별

파일 디스크립터 (file descriptor, FD)
- 프로세스가 열린 파일을 참조할 때 사용하는 정수이다.

`fork()` 후 부모와 자식의 파일 디스크립터 테이블은 각각 존재하지만, 상속된 항목이 같은 열린 파일 상태를 가리킨다.

```text
부모 FD 테이블 ──┐
                 ├── 열린 파일 상태 ── 실제 파일
자식 FD 테이블 ──┘    현재 오프셋 공유
```

따라서 한쪽이 읽어서 파일 위치를 이동시키면 다른 쪽도 이동한 위치를 보게 된다.

#### 예제
```c
/* proc_file.c -- fork 시 파일이 어떻게 취급되는지 보인다 */
main() {
	int fd;
	pid_t pid;
	char buf[10];
	
	if ((fd = open("data", O_RDONLY)) == -1) {
		fatal("open failed");
	}
	
	read(fd, buf, 10);  /* 파일 포인터를 전진시킨다 */
	printpos("Before fork", fd);
	
	switch (pid = fork()) {
	case -1:
		fatal("fork failed");
		break;
	case 0: /* 자식 */
		printpos("Child before read", fd);
		read(fd, buf, 10);
		printpos("Child after read", fd);
		break;
	default: /* 부모 */
		wait((int *)0);
		printpos("Parent after wait", fd);
	}
}

int printpos(const char *string, int filedes) {
	off_t pos;
	
	if ((pos = lseek(filedes, 0, SEEK_CUR)) == -1) {
		fatal("lseek failed");
	}
	
	printf("%s:%ld\n", string, pos);
}
```

가정: `data` 파일에 최소 20바이트가 있고, 읽기 호출이 요청한 바이트 수만큼 성공한다.

| 순서 | 동작 | 현재 파일 오프셋 |
|---:|---|---:|
| 1 | 부모가 파일을 연다. | 0 |
| 2 | 부모가 10바이트 읽는다. | 10 |
| 3 | `fork()`로 자식을 만든다. | 10 |
| 4 | 자식이 읽기 전 위치를 확인한다. | 10 |
| 5 | 자식이 10바이트 더 읽는다. | 20 |
| 6 | 부모가 `wait()` 후 위치를 확인한다. | 20 |

예상 출력:
```text
Before fork:10
Child before read:10
Child after read:20
Parent after wait:20
```

위치를 확인하는 호출은 `lseek(fd, 0, SEEK_CUR)`이다.
현재 위치를 기준으로 0만큼 이동하므로 현재 오프셋을 반환한다.

**암기 포인트**
- 변수의 값은 복제되어 독립적으로 바뀌지만, 상속된 열린 파일의 오프셋은 공유된다.

### 3.8. `fork()`와 `vfork()` 비교
| 항목     | `fork()`               | 강의에서 설명하는 `vfork()`          |
| ------ | ---------------------- | ---------------------------- |
| 메모리    | 부모의 메모리 내용을 복제하여 별도 실행 | 자식이 일시적으로 부모의 주소 공간을 사용      |
| 부모의 진행 | 부모와 자식이 각자 진행 가능       | 자식이 `exec` 또는 종료할 때까지 부모가 정지 |
| 변수 변경  | 일반적인 변수 변경은 서로 독립      | 부모에 영향을 줄 수 있으므로 주의          |
| 대표 용도  | 일반적인 자식 프로세스 생성        | 생성 직후 `execve()`로 프로그램 교체    |
| 자식 종료  | 일반적인 종료 처리 가능          | `exit()` 대신 `_exit()` 사용     |

`exit()`는 표준 입출력 버퍼를 flush하는 등의 처리를 수행한다.
`vfork()`로 생성한 자식이 부모의 상태에 영향을 주지 않도록 `_exit()`로 종료해야 한다.

> **보충 주의**
> `vfork()`의 메모리 공유를 자유로운 변수 수정 용도로 이해하면 안 된다.
> `exec` 또는 `_exit()` 전에는 매우 제한적으로 동작해야 하는 특수한 생성 방식으로 기억하자.

## 4. `exec()`: 현재 프로세스의 프로그램 교체
### 4.1. 무엇이 바뀌는가?
`exec` 계열 함수는 현재 프로세스의 텍스트·데이터·스택 등을 새로운 프로그램 이미지로 교체한다.

```text
exec 전: PID 8328, 기존 프로그램의 코드·데이터·스택
                             |
                            exec
                             |
exec 후: PID 8328, 새 프로그램의 코드·데이터·스택
```

- 새 프로세스를 만드는 함수가 아니다.
- **프로세스의 PID는 유지**된다.
- 기존 프로그램의 코드로 돌아와 계속 실행하지 않는다.
- **성공하면 반환하지 않는다.** 실패하면 `-1`을 반환한다.

```c
execl("/bin/ls", "ls", "-l", (char *)0);

/* 이 줄에 도달했다면 exec가 실패한 것 */
perror("execl");
```

### 4.2. 함수 이름으로 사용법 기억하기
| 글자  | 뜻           | 사용 방식                  |
| --- | ----------- | ---------------------- |
| `l` | list        | 인자를 하나씩 나열             |
| `v` | vector      | 인자 배열 `argv` 전달        |
| `p` | PATH        | 파일명을 `PATH` 환경 변수에서 검색 |
| `e` | environment | 환경 배열 `envp`를 명시적으로 전달 |

강의에서 다루는 여섯 가지 함수의 구분이다.

| 함수 | 프로그램 지정 | 인자 전달 | 환경 |
|---|---|---|---|
| `execl` | 경로 | 나열 | 기존 환경 사용 |
| `execv` | 경로 | 배열 | 기존 환경 사용 |
| `execlp` | `PATH` 검색 가능 | 나열 | 기존 환경 사용 |
| `execvp` | `PATH` 검색 가능 | 배열 | 기존 환경 사용 |
| `execle` | 경로 | 나열 | 환경 배열 지정 |
| `execve` | 경로 | 배열 | 환경 배열 지정 |

```c
/* 인자 나열 + 명시적 경로 */
execl("/bin/ls", "ls", "-l", (char *)0);

/* 인자 나열 + PATH 검색 */
execlp("ls", "ls", "-l", (char *)0);

/* 인자 배열 */
char *const argv[] = {"ls", "-l", NULL};
execv("/bin/ls", argv);
execvp("ls", argv);
```

- 첫 번째 인자: 실행할 프로그램의 경로 또는 파일명
- `arg0` 또는 `argv[0]`: 새 프로그램에 전달할 이름. 보통 프로그램 이름을 넣는다.
- 인자 목록 또는 인자 배열의 마지막: 널 포인터

### 4.3. 왜 `fork()`와 `exec`를 함께 쓸까?
현재 프로세스가 직접 `exec`하면 기존 프로그램이 교체된다.

기존 프로그램을 유지하면서 다른 프로그램을 실행하려면 다음과 같이 한다.
1. 부모가 `fork()`로 자식을 생성한다.
2. 자식이 `exec`로 다른 프로그램을 실행한다.
3. 부모는 자신의 코드를 계속 실행하거나, `wait()`로 자식 종료를 기다린다.

#### 예제
강의의 `ls` 실행 예제에서는 자식이 `/bin/ls -l`을 실행하고, 부모가 기다린 뒤 `ls completed`를 출력한다.
`exec` 성공 시 자식의 기존 코드에 있던 `Child.. I'm here` 출력은 실행되지 않는다.

```c
// execl_test.c: ls 수행
int main(int argc, char *argv[]) {
	pid_t pid, d_pid;
	int exit_status;
	
	if ((pid = fork()) == -1) {
		// fork error 처리
	} else if (pid == 0) {  // child
		execl("/bin/ls", "ls", "-l", (char *)0);
		printf("Child.. I'm here\n\n");  // execl 성공 시 수행 불가
		exit(1);
	} else {  // parent
		printf("pid = %d\n", pid);
		d_pid = wait(&exit_status);
		printf("exit status of task %d is %d\n", d_pid, exit_status);
	}
}
```

### 4.4. 셸 명령 실행: `docommand`
자식에서 다음 호출을 사용한다.
```c
execl("/bin/sh", "sh", "-c", command, (char *)0);
```

| 인자 | 의미 |
|---|---|
| `/bin/sh` | 실행할 셸 |
| `sh` | 셸에 전달할 `argv[0]` |
| `-c` | 다음 문자열을 명령으로 해석하도록 지정 |
| `command` | 실행할 명령 문자열 |

부모는 자식 종료를 기다린다.

#### 예제
```c
// docommand - 셸 명령을 수행한다.
int docommand(char *command) {
	pid_t pid;
	
	if ((pid = fork()) < 0) {
		return (-1);
	}
	
	if (pid == 0) {  // 자식
		execl("/bin/sh", "sh", "-c", command, (char *)0);
		perror("execl");
		exit(1);
	}
	
	// 부모의 코드: 자식이 퇴장할 때까지 기다린다.
	wait((int *)0);
	
	return (0);
}
```

> **예제 해석 보충**
> 강의의 첫 `docommand` 버전은 부모가 기다린 뒤 `0`을 반환한다.
> 이 반환값만으로 실제 셸 명령이 성공했다고 판단할 수는 없다.
> 명령의 결과를 알려면 자식의 종료 상태를 수집하고 해석해야 한다.

### 4.5. `exec` 이후에도 열린 파일은 유지될까?
기본적으로 열린 파일 디스크립터와 현재 파일 오프셋은 새 프로그램에서도 유지된다.
다만 **close-on-exec 플래그가 설정된 FD는 성공한 `exec` 과정에서 닫힌다.**

| FD의 close-on-exec | `fork()` 시 | 성공한 `exec` 시 |
|---|---|---|
| 꺼짐 | FD와 플래그 상속 | FD 유지 |
| 켜짐 | FD와 플래그 상속 | 해당 FD 닫힘 |

강의에서는 `fcntl(fd, F_SETFD, 1)`로 설정하는 예를 제시한다. 의미를 드러내는 상수를 쓰면 다음과 같다.

```c
/* 보충 예제: 오류 처리는 생략 */
int flags = fcntl(fd, F_GETFD);
fcntl(fd, F_SETFD, flags | FD_CLOEXEC);   /* 설정 */
fcntl(fd, F_SETFD, flags & ~FD_CLOEXEC);  /* 해제 */
```

## 5. `exit()`: 종료 코드 남기기
```c
#include <stdlib.h>

void exit(int status);
```

| 종료 코드 | 일반적인 의미 |
|---:|---|
| `0` | 성공 |
| 0이 아닌 값 | 실패 또는 프로그램이 정의한 다른 결과 |

셸에서는 직전 명령의 종료 코드를 `$?`로 확인한다.
```sh
ls nonesuch
echo $?
```

강의 화면에서는 존재하지 않는 파일을 조회한 `ls`의 종료 코드가 `2`이다.
모든 프로그램이 실패에 동일한 코드를 사용하는 것은 아니다.

## 6. `wait()`와 `waitpid()`: 자식의 종료 대기
| 비교 항목    | `wait()`   | `waitpid()`  |
| -------- | ---------- | ------------ |
| 특정 자식 선택 | 불가         | 가능           |
| 기본 동작    | 자식 종료 대기   | 지정한 대상 종료 대기 |
| 비차단 확인   | 지원하지 않음    | `WNOHANG` 사용 |
| 성공 시 결과  | 자식 PID와 상태 | 자식 PID와 상태   |

### 6.1. `wait()`
```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t wait(int *status);
```

- 자식 중 하나의 종료를 기다리고 상태를 수집한다.
- 이미 종료한 자식이 있으면 바로 수집할 수 있다.
- 성공하면 상태를 수집한 자식의 PID를 반환한다.
- 오류이면 `-1`을 반환한다.
- 종료 상태가 필요 없으면 `wait(NULL)`을 사용할 수 있다.

**반환값과 출력 인자를 구별하자.**

```c
pid_t child = wait(&status);
/* child: 자식 PID */
/* status: 종료 방식과 종료 코드 등을 담은 상태 정보 */
```

### 6.2. `status`를 그대로 종료 코드로 읽으면 안 된다
`status`는 단순히 `exit()`에 넘긴 숫자가 아니다.
종료 방식 등의 정보가 함께 인코딩되어 있다.

```c
if (WIFEXITED(status)) {
    int code = WEXITSTATUS(status);
    printf("exit code = %d\n", code);
}
```

| 매크로 | 역할 |
|---|---|
| `WIFEXITED(status)` | 정상적인 종료 경로로 끝났는지 확인 |
| `WEXITSTATUS(status)` | 정상 종료한 자식의 종료 코드 추출 |

예를 들어 자식이 `exit(5)`를 호출하면, 부모는 먼저 `WIFEXITED(status)`를 확인한 뒤 `WEXITSTATUS(status)`로 `5`를 얻는다.

**정상 종료와 성공은 다르다.**
- `exit(5)`도 정상적인 종료 경로이지만, 종료 코드 관례에서는 실패를 뜻할 수 있다.

> **표현 보충**
> 강의는 종료 코드가 `status`의 상위 8비트에 있다고 설명한다.
> 코드를 작성할 때는 비트 위치를 직접 계산하지 말고 제공된 매크로를 사용하자.

#### 예제
```c
int main() {
	int status, exit_status;
	pid_t cpid, pid;
	
	cpid = fork();
	if (cpid == 0) {  // 자식: 무언가 일을 수행한다.
		sleep(5);
		exit(5);
	} else {  // 부모, 따라서 자식을 기다린다.
		pid = wait(&status);
		printf("The child %d is dead\n", cpid);
	}
	
	if (WIFEXITED(status)) {  // 자식이 어떻게 죽었는지 테스트한다.
		exit_status = WEXITSTATUS(status);  // status의 상위 8비트 값
		printf("Exit status from %d was %d\n", pid, exit_status);
	}
	exit(0);
}
```

### 6.3. `waitpid()`: 대상 자식의 종료 대기
```c
pid_t waitpid(pid_t pid, int *status, int options);
```

| 인자 | 강의에서 다루는 사용법 |
|---|---|
| `pid > 0` | 해당 PID의 자식을 기다림 |
| `pid == -1` | 임의의 자식을 대상으로 함. `options == 0`이면 `wait()`와 같은 대기 동작 |
| `options == 0` | 대상 자식의 종료를 기다리는 기본 방식 |
| `options == WNOHANG` | 종료한 대상 자식이 없으면 기다리지 않고 반환 |

`WNOHANG` 사용 시 반환값:

| 반환값 | 의미 |
|---:|---|
| 양수 | 상태를 수집한 자식의 PID |
| `0` | 대상 자식은 있지만 아직 수집할 종료 상태가 없음 |
| `-1` | 오류 |

#### 예제
예제는 자식이 4초 동안 자고 `exit(5)`로 종료하는 동안, 부모가 `waitpid(..., WNOHANG)`으로 확인하고 1초씩 쉰다.

```text
부모: 확인 → 아직 실행 중 → 1초 대기 → 다시 확인
자식: 4초 대기 → exit(5)
부모: 종료 상태 수집 → 종료 코드 5 확인
```

```c
/* status2 - waitpid로 자식의 퇴장 상태를 얻는다 */
main() {
	pid_t pid;
	int status, exit_status;
	
	if ((pid = fork()) < 0) {
		fatal("fork failed");
	}
	
	if (pid == 0) {  /* 자식 */
		printf("Child %d sleeping... \n", getpid());
		sleep(4);
		exit(5);  /* 0이 아닌 값으로 퇴장 */
	}
	
	/* 부모: 자식이 퇴장했는지 확인, 아니면 1초 수면 후 재검사 */
	while (waitpid(pid, &status, WNOHANG) == 0) {
		printf("Still waiting... \n");
		sleep(1);
	}
	
	if (WIFEXITED(status)) {
		exit_status = WEXITSTATUS(status);
		printf("Exit status from %d was %d\n", pid, exit_status);
	}
	
	exit(0);
}
```

> **예제 수정 포인트**
> 강의의 반복문은 `-1` 오류를 별도로 처리하지 않는다.
> 실제 코드에서는 `waitpid()` 성공 여부를 확인한 뒤에만 `status`를 해석해야 한다.
> `Still waiting...`의 정확한 출력 횟수도 스케줄링에 따라 달라질 수 있다.

## 7. 전체 흐름을 연결한 보충 예제
강의의 `fork + exec + wait` 예제를 읽기 쉽게 정리한 코드이다.
`waitpid()`가 인터럽트로 중단된 경우의 재시도와 종료 상태 해석을 포함했다.

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
	pid_t pid = fork();
	
	if (pid == -1) {
		perror("fork");
		return EXIT_FAILURE;
	}
	
	if (pid == 0) {
		execl("/bin/ls", "ls", "-l", (char *)NULL);
	
		/* exec에 성공하면 여기로 돌아오지 않는다. */
		perror("execl");
		_exit(127);  /* 이 예제에서 exec 실패를 나타내는 코드 */
	}
	
	int status;
	pid_t result;
	do {
		result = waitpid(pid, &status, 0);
	} while (result == -1 && errno == EINTR);
	
	if (result == -1) {
		perror("waitpid");
		return EXIT_FAILURE;
	}
	
	if (WIFEXITED(status)) {
		int code = WEXITSTATUS(status);
		printf("child PID=%ld, exit code=%d\n", (long)pid, code);
		return code;
	}
	
	printf("child did not exit normally\n");
	return EXIT_FAILURE;
}
```

읽는 순서:
1. `fork()`의 반환값으로 부모·자식을 구분한다.
2. 자식은 `execl()`로 `ls -l`을 실행한다.
3. 부모는 생성한 자식의 PID를 지정해 기다린다.
4. 부모가 자식의 종료 방식을 확인하고 종료 코드를 얻는다.

> 이 코드는 학습을 위한 보충 예제이다.

## 8. 프로세스의 기타 속성
### 8.1. 현재 작업 디렉터리(Current working directory)
- 프로세스마다 가진 속성이다.
- 자식은 처음에 부모와 같은 현재 작업 디렉터리를 갖는다.
- 자식이 `chdir(path)`로 변경해도 부모의 현재 작업 디렉터리는 바뀌지 않는다.

```text
fork 직후: 부모 /home/user   자식 /home/user
자식 chdir("/tmp") 후:
           부모 /home/user   자식 /tmp
```

### 8.2. 현재 루트 디렉터리
```c
#include <unistd.h>
int chroot(const char *path);
```

프로세스가 파일 경로를 탐색할 때 루트로 사용하는 위치를 바꾸는 기능이다.

| 함수 | 바꾸는 것 |
|---|---|
| `chdir()` | 현재 작업 디렉터리 |
| `chroot()` | 경로 탐색의 루트 디렉터리 |

### 8.3. 파일 크기 제한: `ulimit()`
강의에서는 `<ulimit.h>`의 다음 기능을 소개한다.

| 명령 | 의미 |
|---|---|
| `UL_GETFSIZE` | 파일 크기 제한 조회 |
| `UL_SETFSIZE` | 파일 크기 제한 설정 |

```c
if (ulimit(UL_SETFSIZE, newlimit) < 0)
    perror("ulimit failed");
```

### 8.4. 프로세스 우선순위: `nice(n)`
- nice 값이 클수록 낮은 우선순위를 뜻한다.
- 강의에서는 음수 인자로 우선순위를 높이는 것은 superuser만 가능하다고 설명한다.

> **이해 보충**
> `nice(n)`의 `n`은 일반적으로 현재 nice 값에 더할 증분이다.
> ‘nice 값을 무조건 n으로 설정한다’는 뜻으로 읽지 말자.
> 권한의 세부 조건은 운영체제와 설정에 따라 달라질 수 있다.
