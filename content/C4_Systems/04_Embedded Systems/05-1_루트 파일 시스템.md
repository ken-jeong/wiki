## 1. 먼저 잡아야 할 핵심
**커널이 실행된 것과 사용자가 쓸 수 있는 시스템이 완성된 것은 다르다.**
커널이 루트 파일 시스템을 준비하고, 그 안의 첫 사용자 공간 프로그램인 `init`을 실행해야 셸과 서비스가 시작된다.

| 구성 요소 | 역할 | 기억할 점 |
|---|---|---|
| 부트로더 | 커널·DTB·필요한 초기 파일 시스템을 메모리에 적재하고 커널 실행 | 강의에서는 U-Boot 사용 |
| 커널 | 하드웨어 초기화, 루트 파일 시스템 준비, 첫 사용자 공간 프로그램 실행 | 커널 자체와 사용자 프로그램은 구분 |
| 루트 파일 시스템(rootfs) | `/`를 기준으로 프로그램·라이브러리·설정·디바이스 접근 경로 제공 | 디스크, NFS, 메모리 등으로 구성 가능 |
| init | 첫 사용자 공간 프로세스(PID 1), 셸과 서비스 시작 | 실행할 init이 없으면 부팅 실패 가능 |
| BusyBox | init·셸·기본 명령을 하나의 실행 파일로 제공 | 작은 임베디드 사용자 공간 구성에 사용 |

학습 순서는 다음과 같다.
1. 파일 시스템을 디렉터리에 연결하는 **마운트**를 이해한다.
2. `/`에 사용할 파일 시스템을 **어디에서 가져오는지** 구분한다.
3. rootfs 안에 **무엇이 있어야 프로그램이 실행되는지** 이해한다.
4. BusyBox로 사용자 공간을 구성한다.
5. 부팅 시 가상 파일 시스템과 서비스를 자동으로 시작한다.
6. 완성된 내용을 initramfs로 묶는다.

## 2. 파일 시스템과 마운트
### 2.1. 파일 시스템이란?
**파일 시스템 (File System)**
- 저장 장치나 네트워크의 데이터를 파일과 디렉터리로 구성하는 체계이다.
- 리눅스 사용자는 여러 파일 시스템을 **하나의 디렉터리 계층**으로 접근한다.

**마운트 (Mount)**
- 파일 시스템을 특정 디렉터리에 연결하는 작업이다.
- 연결 지점을 **마운트 포인트**(mount point)라고 한다.

```sh
# 현재 마운트된 파일 시스템을 확인한다.
mount

mount -t <type> <device> <mountpoint>

# 마운트를 해제한다. (캐시 데이터는 저장소에 기록된다.)
umount <mountpoint>
```

| 인자           | 의미                  |
| ------------ | ------------------- |
| `type`       | 파일 시스템 종류           |
| `device`     | 저장 장치 또는 네트워크 위치    |
| `mountpoint` | 해당 파일 시스템에 접근할 디렉터리 |

### 2.2. 루트 파일 시스템은 왜 특별한가?
**루트 파일 시스템 (RFS; Root File System)**
- 디렉터리 계층의 시작점인 `/`를 제공한다.
- 일반적인 저장 장치 루트 부팅에서는 **커널이 직접 루트 파일 시스템을 마운트**한다.

최초 루트 준비를 일반 `mount` 명령 실행에 맡길 수 없다.
- 일반 `mount` 프로그램도 실행 파일이다. 접근하려면 파일 시스템이 먼저 준비되어야 한다.

커널 명령행의 `root=`
- 사용할 루트 장치를 지정한다.

| 저장 위치 | 지정 예 | 해석 |
|---|---|---|
| 디스크·USB 파티션 | `root=/dev/sdb2` | 두 번째 디스크의 두 번째 파티션 |
| SD 카드 파티션 | `root=/dev/mmcblk0p2` | 첫 번째 MMC 장치의 두 번째 파티션 |
| 플래시 파티션 | `root=/dev/mtdblock3` | 번호가 3인, 즉 네 번째 MTD 블록 파티션 |

**구분**
- `/`는 파일 계층의 시작점이다.
- `/root`는 root 사용자의 홈 디렉터리다.

## 3. 루트 파일 시스템을 제공하는 세 가지 방법
| 방법        | rootfs의 위치         | 설정의 핵심                             | 강의에서의 활용                        |
| --------- | ------------------ | ---------------------------------- | ------------------------------- |
| NFS       | 개발 PC의 디렉터리        | `root=/dev/nfs`, `ip=`, `nfsroot=` | 호스트의 파일을 타깃에서 사용                |
| initramfs | 메모리로 풀리는 CPIO 아카이브 | 내장 옵션 또는 부트로더 적재                   | 작은 시스템을 부팅하거나 실제 루트로 전환하는 중간 단계 |
| 저장 장치     | 디스크·SD 카드·플래시      | `root=/dev/...`                    | 장치 파티션을 루트로 사용                  |
> **핵심**:
> NFS는 네트워크에 있는 디렉터리를 사용한다.
> initramfs는 아카이브를 메모리에 풀어서 사용한다.

### 3.1. 일반적인 루트 부팅 흐름
1. 부트로더가 커널과 DTB를 적재하고 커널을 실행한다.
2. 커널이 하드웨어를 초기화한다.
3. 커널이 지정된 루트 파일 시스템을 마운트한다.
4. 커널이 init을 실행한다.
5. init이 셸과 서비스를 시작한다.

### 3.2. initramfs를 사용하는 흐름
1. 부트로더가 커널·DTB·외부 initramfs를 적재한다. 내장 initramfs라면 별도 아카이브 적재는 필요 없다.
2. 커널이 CPIO 아카이브를 메모리의 파일 시스템에 풀어 놓는다.
3. 초기 사용자 공간의 `/init`을 실행한다.
4. 작은 시스템은 이 환경을 계속 사용한다. 중간 부팅 환경으로 사용한다면 실제 루트로 전환하고 그 루트의 init을 실행한다.

## 4. NFS로 루트 파일 시스템 제공하기
**네트워크 파일 시스템 (NFS; Network File System)**

### 4.1. 호스트와 타깃의 역할
- **호스트(개발 PC)**: rootfs 디렉터리를 보관하고 NFS 서버로 공개한다.
- **타깃**: 네트워크를 통해 해당 디렉터리를 자신의 `/`로 사용한다. 강의에서는 QEMU의 ARM 시스템이 타깃이다.

| 항목               | 예제 값                 |
| ---------------- | -------------------- |
| NFS 서버 IP        | `192.168.76.1`       |
| 타깃 IP            | `192.168.76.100`     |
| 호스트의 rootfs 디렉터리 | `/home/user/nfsroot` |

### 4.2. 호스트 설정
```sh
# 호스트에서 실행
mkdir -p ~/nfsroot
sudo apt install nfs-kernel-server
```

`/etc/exports`에 다음 항목을 추가한다.
```sh
vim /etc/exports
```

```text
/home/user/nfsroot 192.168.76.100(rw,no_root_squash,no_subtree_check)
```

| 항목 | 의미 |
|---|---|
| `/home/user/nfsroot` | 공개할 호스트 디렉터리 |
| `192.168.76.100` | 접근할 타깃 주소 |
| `rw` | 읽기·쓰기 허용 |
| `no_root_squash` | 클라이언트 root의 접근을 익명 사용자 권한으로 바꾸지 않음 |
| `no_subtree_check` | 하위 디렉터리 트리 검사 비활성화 |

변경 사항을 다시 읽게 한다.
```sh
sudo exportfs -r
```

### 4.3. 타깃 커널 설정
```sh
cd ~/linux
make menuconfig
```

루트를 준비하는 데 필요한 기능을 커널에 내장하는 `=y`로 설정한다.

| 커널 옵션               | 목적                  | menuconfig                                  |
| ------------------- | ------------------- | ------------------------------------------- |
| `CONFIG_IP_PNP=y`   | 부팅 중 IP 설정 지원       | Networking support<br>-> Networking options |
| `CONFIG_NFS_FS=y`   | NFS 클라이언트 지원        | File systems<br>-> Network File Systems     |
| `CONFIG_ROOT_NFS=y` | NFS를 루트 파일 시스템으로 사용 | File systems<br>-> Network File Systems     |

### 4.4. U-Boot의 커널 인자
```text
root=/dev/nfs
ip=192.168.76.100
nfsroot=192.168.76.1:/home/user/nfsroot,nfsvers=3,tcp
rw
```

| 인자 | 의미 |
|---|---|
| `root=/dev/nfs` | NFS 루트 사용 |
| `ip=192.168.76.100` | 타깃의 IP |
| `nfsroot=서버IP:경로` | NFS 서버와 공개 디렉터리 |
| `nfsvers=3,tcp` | NFS 버전 3과 TCP 사용 |
| `rw` | 루트를 읽기·쓰기 모드로 사용 |

강의의 U-Boot 예제:
```sh
=> setenv bootargs ${bootargs} root=/dev/nfs ip=192.168.76.100 nfsroot=192.168.76.1:/home/user/nfsroot,nfsvers=3,tcp rw
=> saveenv
```
> 기존 `bootargs`에 추가하는 형태이므로, 반복 실행 시 인자가 중복되지 않도록 기존 값을 확인한다.

### 4.5. 마운트 성공과 부팅 성공은 다르다
```sh
cd ~/u-boot
sudo qemu-system-arm \
  -M vexpress-a9 \
  -m 128M \
  -nographic \
  -audio none \
  -kernel u-boot \
  -drive file=sd.img,if=sd,format=raw \
  -nic tap,script=./qemu-myifup,downscript=no
```

> 빈 nfsroot를 사용하면 다음 로그가 나타난다.

```text
VFS: Mounted root (nfs filesystem) on device 0:13.
```
이 메시지는 **NFS 루트 마운트에 성공했다**는 뜻이다.
다음 사용자 공간 실행까지 성공했다는 뜻은 아니다.

```text
devtmpfs: error mounting -2
```
강의 실습에서는 rootfs에 `/dev` 디렉터리가 없다.
→ 호스트에서 `/dev` 마운트 지점을 준비한다.
```sh
mkdir -p ~/nfsroot/dev
```

```text
Kernel panic - not syncing: No working init found.
```
실행 가능한 init 및 그 실행에 필요한 파일이 없다.
→ **init 부재는 BusyBox 등을 설치해 별도로 해결해야 한다.**

## 5. 루트 파일 시스템 안에는 무엇이 있는가?
### 5.1. 주요 디렉터리
**파일시스템 계층구조 표준 (FHS; Filesystem Hierarchy Standard)**

| 경로          | 역할                            |
| ----------- | ----------------------------- |
| `/bin`      | 기본 사용자 명령                     |
| `/sbin`     | 기본 시스템 관리 명령                  |
| `/lib`      | 기본 라이브러리                      |
| `/boot`     | 커널 이미지, 설정, initramfs         |
| `/dev`      | 디바이스 파일                       |
| `/etc`      | 시스템 전체 설정                     |
| `/home`     | 일반 사용자 홈 디렉터리                 |
| `/root`     | root 사용자 홈                    |
| `/proc`     | 프로세스·커널 정보를 제공하는 proc 마운트 지점  |
| `/sys`      | 장치·드라이버 정보를 제공하는 sysfs 마운트 지점 |
| `/run`      | 실행 중 생성되는 가변 데이터              |
| `/tmp`      | 임시 파일                         |
| `/var`      | 로그, 스풀 등 서비스의 가변 데이터          |
| `/usr/bin`  | 추가 프로그램                       |
| `/usr/sbin` | 시스템 관리 명령                     |
| `/usr/lib`  | 라이브러리                         |
| `/media`    | 이동식 미디어 마운트 지점                |
| `/mnt`      | 임시 마운트 지점                     |

### 5.2. proc와 sysfs 비교
이들은 일반 저장 파일을 모아 놓은 디렉터리와 달리, **커널이 정보를 파일 형태로 보여 주는 가상 파일 시스템**이다.
디렉터리 생성과 파일 시스템 마운트는 별개의 작업이다.

| 구분 | proc | sysfs |
|---|---|---|
| 마운트 위치 | `/proc` | `/sys` |
| 주요 내용 | 프로세스 상태, 커널·시스템 정보와 일부 조정 항목 | 버스·장치·드라이버 구조 |
| 활용 예 | `ps`, `top` | `udev`, `mdev`의 장치 정보 확인 |
| 명령 | `mount -t proc nodev /proc` | `mount -t sysfs nodev /sys` 

proc에서 확인하는 항목:
```sh
cat /proc/cpuinfo       # CPU 정보
cat /proc/cmdline       # 실제 커널 명령행
cat /proc/interrupts    # 인터럽트 정보
cat /proc/iomem         # 메모리 주소 영역 정보
cat /proc/3840/cmdline  # PID 3840의 실행 명령행
```

`/proc/sys`는 커널 파라미터 조정에 사용한다.
강의의 `echo 3 > /proc/sys/vm/drop_caches`는 상태를 읽는 명령이 아니라 캐시 해제를 요청하는 쓰기 예제다.

**실습 연결**:
- `ps: can't open '/proc'`가 나오면 `/proc` 디렉터리와 proc 마운트 상태를 확인한다.

### 5.3. 최소 사용자 공간
최소한 다음 요소가 필요하다.
1. **init**: 부팅 후 사용자 공간 초기화와 서비스 시작
2. **셸**: 사용자와 시스템의 명령어 인터페이스
3. **기본 명령**: `cp`, `mv`, `mkdir`, `cat`, `mount`, `ip`, `modprobe` 등
4. **실행에 필요한 라이브러리·로더**: 동적 링크 프로그램을 사용할 때 필요

일반 루트 부팅에서 강의가 설명하는 init 선택 과정:
1. `init=`로 지정한 프로그램이 있으면 실행을 시도한다.
2. 별도 지정이 없으면 `/sbin/init` → `/etc/init` → `/bin/init` → `/bin/sh` 순서로 시도한다.
3. 실행할 프로그램을 찾지 못하면 panic이 발생하고 부팅이 멈춘다.

initramfs의 초기 진입점
- 기본적으로 `/init`이며, `rdinit=`으로 다른 경로를 지정할 수 있다.

**init**
- 서비스를 시작한다.
- 부모를 잃은 프로세스를 맡는다.
- 일반 루트의 `init=`과 초기 RAM 파일 시스템의 `rdinit=`을 구분하자.
