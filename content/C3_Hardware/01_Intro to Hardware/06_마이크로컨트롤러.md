> 본 장은 **ATmega128**을 기준으로 설명한다. 그러나 대부분의 MCU가 거의 동일한 구조를 갖기 때문에, 하나의 MCU만 잘 이해하면 다른 MCU들도 쉽게 사용할 수 있다.

## 1. 마이크로컨트롤러 개요

### 1.1. MCU의 특징
- **MCU**(Micro Controller Unit)라고 부른다.
- 하나의 칩에 다양한 기능을 내장하여 **독자적으로 동작이 가능**한 칩 → ==칩 하나로 집약된 컴퓨터==
	1. 중앙처리장치 (MPU = CPU)
	2. 메모리 (SRAM, EEPROM, Flash Memory 등)
	3. 주변기기 제어 회로
- 다른 시스템의 일부로 사용되는 경우가 흔함 → **임베디드 시스템**
- 일반 컴퓨터용 프로세서에 비해 **낮은 사양**이며, **전용의 단순한 목적**을 갖는다.

### 1.2. MCU vs MPU
- **마이크로프로세서**(MPU = CPU)
	- 중앙처리장치 기능을 하나의 IC 칩으로 집적시켜 만든 반도체 소자
	- 1969년 인텔의 4비트 uP인 **4004**에서 시작
	- 4004는 약 2,300개 TR, i7은 약 22억 개 TR 사용
- **마이크로컨트롤러**(MCU)
	- ==**MCU = MPU + 메모리 + 입출력 인터페이스**==
	- 컴퓨터의 **메인보드와 하드디스크 기능**을 하나의 IC 칩으로 집적시켜 만든 반도체 소자
	- 단일 칩 마이크로컴퓨터, '마이컴'이라고도 한다.
	- 작고 간단한 제어장치를 만들기 위한 목적으로 특화된 마이크로프로세서의 한 종류

### 1.3. MCU의 장단점
- **장점**
	1. 제품의 **소형화**
	2. **경량화**
	3. **저렴한 가격**
	4. **신뢰성** 향상
	5. **융통성** — 변경 시 회로가 아닌 **프로그램**의 변경
	6. 다양한 종류의 제품이 존재 — 용도에 맞게 최적화 선택 가능
- **단점**
	1. 낮은 처리 능력
	2. 범용성 부족

### 1.4. 주요 MCU의 종류
1. **8051** (인텔, Atmel, TI, Maxim, Winbond) — 8비트 **CISC**
2. **PIC 시리즈** (마이크로칩) — 8, 16, 32비트 **RISC**
3. **AVR 시리즈** (Atmel) — 8, 32비트 RISC, ==**아두이노**에서 사용==
4. **ARM 계열** — 32, 64비트 RISC, ==**라즈베리파이**에서 사용==

## 2. 마이크로컨트롤러의 구조

### 2.0. 구성 모듈
1. CPU (Core)
2. 메모리 모듈
3. 클럭 발생 모듈
4. GPIO(디지털 I/O) 모듈
5. 타이머/카운터 모듈
6. PWM 모듈
7. Interrupt controller 모듈
8. A/D converter 모듈
9. 아날로그 비교기 모듈
10. USART 모듈
11. SPI 모듈
12. I2C 모듈
13. 기타 (D/A converter, USB, WiFi, CAN, Ethernet 등)

> 대부분의 MCU가 이러한 모듈들을 기본적으로 갖는다. ==**CPU에서 설정만 해 주면 CPU와 무관하게 동작**되며 필요시에만 CPU와 정보를 교환한다.== 성능·채널 수는 회사마다, 같은 회사 내에서도 MCU마다 다를 수 있다.

### 2.1. CPU (Core)
1. **RISC 구조**로 설계
	- **파이프라인** 적용으로 빠른 실행 속도 지원
	- 근래에는 대부분 MCU 개발에 고급언어(C)를 사용하며 컴파일러 성능도 좋아져 RISC 사용에 문제가 없다.
2. **Harvard(하버드) 구조** 사용
	- ==명령어와 데이터를 **전용의 메모리에 나누어 저장**==
	- 하드웨어는 복잡해지지만 **병목 현상 해소**의 한 방법
	- 프로그램 주소공간과 데이터 주소공간을 분리해 사용하기도 한다.
3. **다양한 레지스터 종류** (CPU 주소공간에서 모든 레지스터의 주소가 다름)
	- **CPU에서 사용하는 레지스터** (고급언어 프로그래머가 신경 쓰지 않아도 됨)
		- 특수 레지스터 (SP, Program Status Word, IR 등)
		- 범용 레지스터 → 컴파일러가 지정 (ATmega128은 32개)
	- **입출력 제어용 특수 레지스터** (==프로그래머가 세부 내용을 이해하고 프로그래밍해야 함==)
		- CPU 고유의 기능 이외의 모든 기능을 제어하는 입출력 레지스터
		- ① 기능의 설정 ② 상태 확인, 입출력 기능으로 사용
		- ==MCU는 **핀 수가 많아지면 IC 크기가 커져 가격이 오르므로**, 동일한 핀을 여러 용도로 사용한다. 따라서 원하는 기능으로 쓰려면 레지스터를 프로그래밍해 해당 핀의 기능을 설정해 주어야 한다.==

### 2.2. 내부 메모리
> MCU 내부에는 일반적으로 세 종류의 메모리가 칩 내부에 존재한다.

1. **플래시 메모리**: 프로그램 저장 및 프로그램 실행 준비를 위한 **메인 메모리** 기능
	- ==임베디드 시스템에서는 **HDD를 거의 사용하지 않는다**== (신뢰성 이슈)
2. **SRAM**: 연산용, 컴퓨터의 메인 메모리 기능
3. **EEPROM**: 데이터 **영구보관**용

- 일부 MCU에서는 Flash 메모리에서의 실행속도가 늦어서 이를 **SRAM으로 옮겨서** 프로그램을 실행시키기도 한다.

### 2.3. 클럭 발생 모듈
- 디지털 시스템 동작의 기준이 되는 신호로, MCU 내부에 다양한 클럭들이 존재한다.
- 외부 또는 내부의 클럭을 이용해 **시스템 클럭(기준 클럭)**을 생성하며, 사용자가 레지스터로 선택한다.
- 시스템 클럭을 이용해 다양한 **내부 모듈용 클럭**을 생성한다.

- **클럭 소스 연결 방법 (ATmega128)**
	1. 외부 RC 오실레이터
	2. 외부 X-TAL
	3. 외부 저주파 X-TAL (32.768KHz)
	4. **내부 RC 오실레이터** → 외부 부품 없이 구동하는 경우
	5. 외부 클럭 소스 (OSC 등)

### 2.4. 전원 관리와 슬립 모드
- MCU는 **배터리**로 전원을 사용하는 경우가 많다.
- 따라서 다양한 **슬립(sleep) 모드**를 지원해 상황에 맞게 각 모듈에 공급되는 **클럭을 중지**해서 전원 사용을 최소화한다. (Power consumption의 최소화)
- 설정 레지스터에 값을 쓰면 슬립모드로 진입하며, 다양한 조건에 의해 해제(**wake-up**)된다.
- **AVR(ATmega128) 계열의 슬립모드** — 각각 Power consumption이 모두 다르다
	1. Idle 모드
	2. ADC noise reduction 모드
	3. Power-down 모드
	4. Power-save 모드
	5. Standby 모드
	6. Extended Standby 모드

### 2.5. 리셋(Reset)과 워치독(Watchdog)
- **리셋의 기능**
	- MCU가 리셋되면 입출력 레지스터는 **초기화**되고, 프로그램은 시작번지가 저장되어 있는 **리셋 벡터**에서 시작한다.
	- 리셋 벡터에는 리셋 처리 장소로 이동하기 위한 **JMP 명령어**가 있다.

- **리셋의 종류**
	1. **파워온 리셋**(POR): 공급 전압이 파워온 리셋 **임계전압 이하**일 때 리셋
	2. **외부 리셋**: 리셋 핀에 일정시간 이상의 신호가 입력되면 리셋
	3. **워치독 리셋**: 워치독 타이머에서 지정된 시간이 넘으면 리셋
	4. **브라운아웃 리셋**: 공급전압(VCC)이 브라운아웃 임계전압 이하로 떨어지면 리셋
	5. **JTAG 리셋**: JTAG 시스템에서 리셋 레지스터에 1을 저장하면 리셋

- **워치독 리셋** (Watchdog)
	- **목적**: MCU가 소프트웨어적인 문제로 **무한 루프**에 빠지거나 비정상 동작을 할 경우, 워치독 타이머로 MCU를 리셋시켜 **재시동**할 수 있게 한다.
	- 타이머 값은 사용자가 레지스터로 설정 가능하다.
	- ==타이머가 지정된 카운트 값에 도달하기 전까지 지정 레지스터에 **쓰기 작업**이 필요하다.==
		- 쓰기 작업을 하지 않으면 리셋 발생 → MCU 새로 시작
		- 오버플로우 전에 쓰기 작업을 하면 타이머는 **초기값**이 되며 다시 카운트를 시작한다.
	- 사용자가 이 기능의 사용 여부를 설정할 수 있다.

- **브라운아웃 리셋** (Brown-out Reset)
	- 공급 전압이 일정 값 이하로 떨어질 때 리셋을 발생시켜 **비정상적인 동작을 방지**하는 기능
	- ==정상동작 보증 전압보다 살짝 낮을 경우 CPU가 동작될 가능성은 높으나, 이때의 동작 결과는 **신뢰할 수 없다.**==
	- 사용자가 레지스터로 브라운아웃 전압을 설정할 수 있다.

### 2.6. GPIO 모듈 (General Purpose Input Output)
- MCU와 다양한 **디지털 입출력장치를 연결하는 통로**
- 데이터 입출력은 비트 단위인 0/1 데이터가 기본이며, ==**8개(비트) 단위로 하나의 GPIO 포트**를 구성==한다.
- 레지스터를 이용해 다음을 수행한다.
	1. 핀의 용도 결정 → 미사용, 입력 또는 출력 설정
	2. 내장 **풀-업 저항**의 사용 여부 (SFIOR 레지스터로 설정)
	3. 핀 입력 데이터 읽기
	4. 출력 데이터 쓰기

- **GPIO 포트 레지스터 (ATmega128)**
	1. **DDRx**(Data Direction Register): 데이터 **입출력 방향**의 결정 (1=출력, 0=입력)
	2. **PORTx**: 데이터 **출력** 레지스터
	3. **PINx**(Port Input Pins Register): 데이터 **입력** 레지스터
- ==하나 또는 두 핀만의 방향을 설정하려고 해도 **8비트 모두 설정**되므로, 앞서 설정된 정보를 추적해야 한다.== (다른 비트 정보가 잘못 변경되는 것을 피하기 위해 기존 값을 알고 있어야 함)

- **풀업/풀다운 저항**
	- 회로가 개방된 경우 **플로팅(floating)** 되어 입력 핀에 가해지는 값을 알 수 없다.
	- **풀업**: 버튼이 눌러지지 않은 경우 입력 핀에 **5V(HIGH)**가 가해지도록 보장
	- **풀다운**: 버튼이 눌러지지 않은 경우 입력 핀에 **GND(LOW)**가 가해지도록 보장
	- 대부분의 MCU가 **내부에 풀업 저항을 내장**해서 사용자가 회로설계를 편하게 할 수 있게 지원한다.

- **채터링과 디바운스**
	- **채터링**(Chattering) = **바운스**(Bounce) 현상
		- 스위치의 **기계적인 진동**에 의해 잠시 동안 원하지 않는 상태가 빠르게 변하는 현상 → 순간적으로 On/Off를 반복
	- **디바운스**(Debounce): 바운스 현상을 제거하는 방법
		1. **소프트웨어**에 의한 방법: **시간 지연**을 통해 버튼의 빠른 상태 변화 무시
		2. **하드웨어**에 의한 방법: **커패시터**를 통해 버튼의 빠른 상태 변화 무시

- *참고: 아두이노 우노(Uno) R3 보드 — ATmega328P 사용*
	- *GPIO 포트 13핀 (`~` 표시가 된 핀은 **PWM 출력** 가능, 0·1번 핀은 통신용도로도 사용 가능)*
	- *아날로그 포트 6핀 (**10비트 ADC** 용도)*
	- *내장 LED(13번 핀), 리셋 스위치, USB 커넥터(전원 공급·프로그램 다운로드·직렬 모니터), 보조 전원*

### 2.7. 타이머/카운터 모듈
- 어떤 **클럭 펄스를 카운트**하는 장치로 복수개의 타이머/카운터 기능을 갖는다.
	- ==**CPU의 부담이 전혀 없이** 기능을 수행한다.==
	- 인터럽트 기능과 함께 사용할 경우 다양한 기능을 구현할 수 있다.
	- ==타이머 동작과 카운터 동작을 **동시에 수행할 수 없다.**== (사용자의 레지스터 설정에 따라 결정)

- **타이머로 동작**: MCU **내부**의 시스템 클럭을 카운트
	- 설정된 일정 시간에 또는 반복적으로 **인터럽트**를 발생시킬 수 있다.
	- 내부 시스템 클럭은 일정한 주기를 가지므로 결과적으로 **시간을 카운트**할 수 있다. (1Hz 클럭 5개 = 5초)
- **카운터로 동작**: MCU **외부**에서 입력되는 클럭을 카운트
	- 외부 입력 클럭은 주기가 불규칙할 수 있어 **클럭의 개수만** 카운트한다.
	- 일정 시간 동안 입력되는 클럭 개수를 카운트하여 **주파수**로 변환할 수 있다.

- **필요성**
	1. **CPU 부담 없이 시간 경과**를 알 필요가 있다. (CPU로 지연을 구현하면 다른 일을 못해 효율이 나빠짐)
	2. **CPU 부담 없이 주기적인 펄스 출력**이 필요하다. (스케줄링, PWM 지원)
	3. **CPU 부담 없이 외부 펄스의 정확한 발생 시각**을 알 필요가 있다.
		- 언제 발생할지 모르므로 **폴링으로 감지하기 어렵다.**
		- **입력 캡처** 기능: 외부 펄스가 발생한 순간의 카운터 값을 하드웨어적으로 저장

### 2.8. PWM 모듈 (Pulse Width Modulation, 펄스 폭 변조)
- 일정한 주기로 일정 구간은 On 신호를, 일정 기간은 Off 신호를 반복적으로 출력
	- 주기, On 기간, Off 기간 등 모든 항목을 사용자가 레지스터로 설정한다.
	- **타이머/카운터 모듈의 부가 기능**이다.
- ==디지털 정보를 아날로그로 변화하기 위한 가장 기본적인 방법==
	- **DAC는 고가**이기 때문에 PWM을 많이 사용한다. (일부 고가 MCU는 DAC 모듈을 내장)
	- LED 밝기, 모터 제어 등 매우 다양한 용도로 사용
	- 소프트웨어적으로도 구현할 수 있으나 **CPU에게 엄청난 부담**을 준다. → MCU 선정 시 필요한 PWM 채널 수 지원 여부를 신중히 고려해야 한다.

- **PWM 용어**
	- **주기**(Period): 하나의 PWM 파형이 반복되는 시간 (On 시간 + Off 시간)
	- **On 시간**(Pulse width) / **Off 시간**
	- **듀티비**(Duty Ratio, 듀티 사이클) = On 시간 / 주기 → '%'로 표시
		- ==이 값에 의해 **아날로그 값(전압)**이 결정된다.== (100%=최대값, 0%=최소값, 50%=중간값)

- **동작 원리**: 디지털 값인 듀티비를 조절하여 아날로그 값인 **평균 전압**을 가변한다.
	1. PWM 주기를 결정해 레지스터에 설정
	2. On 기간과 Off 기간을 레지스터에 설정
	3. 레지스터를 통해 PWM 동작을 실행
	4. 아날로그 값을 변경할 경우 새로운 듀티비를 레지스터에 설정

### 2.9. 인터럽트 컨트롤러 모듈
- **폴링**(Polling)
	- 주 프로그램 안에서 CPU 명령어로 **반복적으로 장치 상태를 검사**하는 방식 → ==비효율적==
	- **레벨감지 폴링**(전압레벨 값 감지) / **에지감지 폴링**(전압레벨 값의 변경 감지)
- **인터럽트**(Interrupt)
	- 설정된 내·외부의 **사건(event)**을 CPU와 무관하게 감시하다가, 발생 시 CPU에게 알려 해당 **ISR**(Interrupt Service Routine)을 실행하게 하는 메커니즘
	- 특정 상황의 발생 여부를 CPU가 매번 확인하는 **폴링을 배제**할 수 있다.
	- MCU에서는 특히 **입출력 모듈과 관련된** 많은 인터럽트를 지원한다.
- **인터럽트 컨트롤러**
	- 복수개의 인터럽트가 발생할 때 **우선순위**에 맞게 순서를 정리해 CPU에게 요청하는 기능
	- 특정 MCU는 인터럽트 진행 중 더 높은 우선순위 요청 시 이를 먼저 처리한다. (**중첩 인터럽트**)
	- 개별 인터럽트 기능 사용 여부는 레지스터를 통해 설정한다.

- **인터럽트 벡터**(Vector): 인터럽트가 발생했을 때 해당 인터럽트를 처리할 **ISR의 메모리 주소**
- **인터럽트 벡터 테이블**: 많은 인터럽트들에 대한 벡터를 모아 놓은 테이블 (==CPU마다 지정된 위치가 다르다==)

- **인터럽트 처리 순서**
	1. 인터럽트의 발생
	2. 인터럽트 벡터 테이블에서 해당 벡터를 참고해 ISR의 주소를 가져옴
	3. 해당 ISR로 이동
	4. ISR 처리
	5. 인터럽트 처리 이전에 수행하던 코드로 되돌아감

- **인터럽트의 종류** (ATmega128은 **35개**의 인터럽트를 지원)
	1. **외부 장치 인터페이스용**: 8개의 외부핀 인터럽트 제공
	2. **내부 장치 인터페이스용**: EEPROM, USART, ADC 등 내장 장치와의 인터페이스
	3. **타이머 인터페이스용**: 타이머/카운터 모듈과 관계된 인터럽트

### 2.10. A/D Converter 모듈
- 현실 세계는 대부분 아날로그로 구성되어 있어, MCU는 디지털로 변환된 데이터를 입력받아 처리·저장한다.
- **MCU에서 아날로그 값을 디지털로 변환하는 방법**
	1. **디지털 입력 핀**: 제한된 범위 내에서 0, 1 값으로만 입력 → **1비트**
	2. **아날로그 비교기**: 설정된 값보다 클 경우만 1로 입력 → **1비트**
	3. **A/D Converter**: 입력 아날로그 값을 다단계의 디지털 값으로 변환 → **n비트**
- 변환 과정: **표본화(샘플링) → 양자화 → 부호화**

- **ADC의 주요 성능** — ==서로 상반되는 특성을 갖기 때문에 용도에 맞는 적절한 선택이 필요==
	1. **분해능력**: 몇 비트의 디지털 값으로 변경할 것인지 (0V~Vref 범위를 몇 단계로 디지털화)
		- 일반적인 MCU: **8비트(256단계), 10비트(1024단계)**
		- 특수 고가형 MCU: 12비트(4096단계)
	2. **변환속도**: 변환하는 데 소요되는 시간
		- MCU 내부 ADC는 노이즈 방지를 위해 다른 모듈의 클럭을 죽이고 변환하기도 하므로, **필요 이상 자주 변환작업을 하지 않는 것도 중요**하다.
	3. **직선성**: 모든 범위 내에서 얼마나 정확하게 표현되는지

- **입력 방법**
	- **단일 입력**: 1개의 입력과 GND를 사용 / **차동(differential) 입력**: 2개의 입력 차이와 GND를 사용
	- **이득**(gain): 입력 아날로그 신호가 작은 경우 증폭 기능 사용 가능 (10배, 200배)

### 2.11. 아날로그 비교기 모듈
- ==**CPU와 무관하게 동작**하는 모듈==
- 2개의 아날로그 입력전압(**AIN0, AIN1**)을 비교하는 내장 회로 모듈
	- AIN0가 AIN1보다 크면 결과 레지스터에 **1**, 그렇지 않으면 **0**이 반영
- 설정에 따라 비교기의 결과를 **인터럽트 발생** 또는 **타이머/카운터의 입력 캡처 트리거** 신호로 사용할 수 있다.
- 굳이 ADC 변환을 하지 않고 간단하게 아날로그 값 비교 기능을 할 때 사용된다.
	- 예: 유량센서 경고 및 제어 — 최고치 값(AIN1)을 저항으로 미리 설정하고, 센서 값(AIN0)과 비교해 도달 시 인터럽트를 발생시켜 ISR에서 경고음과 함께 밸브를 잠금

### 2.12. USART 모듈

#### 통신속도 용어
- **Baud rate**: 초당 최대 몇 번의 **신호가 변화**할 수 있는지의 값
- **bps**(bit per second): 1초에 얼마만큼의 **데이터 비트**를 전송할 수 있는지의 단위
- 1회의 변조로 4비트를 보내면 600 baud = 2400bps
- ==일반적인 디지털 시스템에서는 1회 변조로 1비트만 보내므로 **baud rate와 bps는 같은 개념**으로 이해해도 된다.==

#### 동기화 여부에 따른 분류
- **동기식**(Synchronous): 데이터 라인 외에 **기준 클럭(동기 클럭) 라인**이 있음
	- 데이터를 기준 클럭에 동기시켜 순차적으로 송수신
	- 비동기 방식에 비해 **비용이 많이 들지만 통신의 안정성이 좋음**
	- 예: **SPI, I2C**(2-Wire)
- **비동기식**(Asynchronous): 동기 클럭 없이 데이터만 송수신
	- ==송수신 모듈에서 **동일한 통신속도 설정이 필요**== (다르면 읽히는 값이 달라짐)
	- 예: **UART**

#### 대표적인 직렬통신 방식
- **UART**(Universal Asynchronous Receiver and Transmitter)
	- 대표적인 비동기식 직렬 전송 방식 → 모니터링용 터미널 등에 사용
	- 신호레벨과 전송매체에 따라 **RS-232, RS-422, RS-485** 등의 표준 규격이 있다.
	- *USART를 이용한 동기식 전송방식은 거의 사용하지 않으며, 비동기식만 지원하는 경우 UART라고 한다.*
- **SPI**: 4개의 선으로 이루어진 **고속**의 동기식 직렬통신
- **I2C**(TWI): SDA, SCL의 **2선**으로 이루어지는 **저속**의 동기식 직렬통신
- 기타: USB, SATA, IEEE1394, PCI Express, Ethernet, **CAN**(Controller Area Network)

#### UART 프레임 포맷 (Frame Format)
> 직렬 전송 시의 데이터 포맷으로, ==송/수신측의 설정 값이 동일해야 한다.== 속도(baud rate)를 포함한 모든 구성 정보는 레지스터에 기록해 설정한다.

1. **시작 비트(St)**: 새로운 프레임이 시작되면 반드시 **0**으로 1비트 시간
2. **데이터 비트**: **5~9비트** 중에서 선택, ==**LSB부터 MSB까지** 차례로 전송==
3. **패리티 비트(P)**: 1의 개수가 지정된 개수와 다를 경우 자동으로 **전송 에러** 처리
	- odd parity / even parity / none parity
4. **정지 비트**: 프레임과 프레임 사이를 구분, **1 또는 2**로 설정

#### UART 통신부의 구성
1. **클럭 발생부**: 전송속도 발생기와 클럭 동기 회로
2. **전송부**: 송신 버퍼 레지스터, 송신 시프트레지스터, 패리티 발생기
3. **수신부**: 수신 버퍼 레지스터, 수신 시프트레지스터, 패리티 검사기
4. **인터럽트 발생부**
	- ① 송신완료(TX Complete) ② 송신 데이터 레지스터 준비완료(TX Data Register Empty) ③ 수신완료(RX Complete)

- **송신 과정**: 송신 레지스터 → 송신 시프트 레지스터 → 시작 비트 출력 후 **LSB부터 1비트씩** TxD 핀으로 출력 → 패리티 비트 생성·출력 → 전송완료 기록 및 인터럽트 발생
- **수신 과정**: RxD 핀의 시작 비트 신호에 클록을 맞춤 → 한 비트씩 읽어 수신 시프트 레지스터에 입력 → 패리티 검사 → 정지 비트 검사 후 수신 레지스터로 복사 → 수신완료 기록 및 인터럽트 발생

#### RS-232 / RS-422 / RS-485
> UART의 입출력은 **TTL 레벨**이기 때문에, 외부에 해당 인터페이스용 **라인 드라이버 IC**를 추가해 사용한다.

| | **RS-232** | **RS-422** | **RS-485** |
|---|---|---|---|
| 전송 방식 | **Full-duplex** | Full-duplex | **Half-duplex** |
| 신호선 | GND, Tx, Rx (3선 필수) | TXD±, RXD± (4선, GND 미사용) | 1쌍(+, −) **2선** |
| 전압 | +12V(mark), −12V(space) | 0V, 5V **차동신호** | 차동신호 |
| 구조 | 1:1 | **1:n** (마스터는 오직 하나) | **멀티 마스터** |

- **RS-232c**
	- **EIA**에서 전화선을 이용한 데이터 통신용으로 제정한 규격
	- 9개의 신호가 규정되어 있으나 **RxD, TxD, GND의 3선만으로도 기본 통신이 가능**
	- MCU의 TTL 레벨을 ±12V로 바꾸어 주는 **라인 드라이버 IC**가 외부에 필요하다.
	- ==**DTE와 DTE 간**에는 RxD, TxD 선을 서로 **꼬아주며**, DTE-DCE 간에는 바로 연결==
		- *DTE: 데이터를 만들어내는 데이터 단말기 / DCE: DTE로부터 받은 데이터를 다른 형태로 바꾸어 통신하는 장비 (컴퓨터↔모뎀)*
	- 임베디드 시스템 개발 시 **콘솔(console)용** 장비에 연결해 동작상태를 모니터링하는 용도로 많이 사용 → 화면 출력이 없는 시스템에서 매우 유용
	- USB의 출현으로 PC에서는 사라지고 있으나 역사적으로 중요한 방식
- **RS-422**
	- 하나의 신호선에서 **2개의 라인(차동신호)** 사용
	- **차동신호**(differential signal): 데이터 값을 '+', '−'로 변환해 2선으로 보내고, 수신측에서 두 선의 **전압 차이**로 데이터를 복원
		- ==노이즈가 유입되어도 **2선에 동시에** 유입되고, 신호 차이로 복원하므로 노이즈 영향이 거의 없다.== → **고속·장거리 전송 가능**
	- 연결 방식: **Point to Point**(1:1) / **Multi-drop**(1:n, 마스터/슬레이브)
	- **마스터/슬레이브** 방식: 하나의 신호선 묶음에 복수 장치를 연결(신호선 공유)하고, 마스터의 지시로 선택된 슬레이브만 데이터를 전송
		- 복수 장치가 마스터가 될 수 있는 경우를 **멀티 마스터** 방식이라 하며, 특정 순간에는 오직 하나만 마스터가 된다.
- **RS-485**
	- 전기적으로는 RS-422와 동일한 차동방식이나, 송·수신선이 분리되지 않고 **하나의 신호선 쌍**으로 구성 (Half-duplex)
	- **멀티 마스터** 구조 — 모든 장치가 특정 순간에 마스터가 될 수 있다.
	- ==**산업현장에서 매우 많이 사용**된다.== 2가닥만 사용하면서도 노이즈에 강하고(차동방식), RS-422보다 선이 적어 저비용·간편하다.

### 2.13. SPI 모듈 (Serial Peripheral Interface)
- I2C에 비해 동작 방법이 **간단하고 통신 속도가 빠름** (20Mbps 이상)
- MCU와 주변 장치 간에 **1:1 전이중 방식**으로 고속의 **동기** 데이터를 전송하는 직렬 통신
	- ADC, EEPROM, Flash, 센서, SD 카드 등 외부 주요 부품과의 통신에 활용
- **마스터 또는 슬레이브 동작**
	- 보통 주변 장치가 마스터, MCU는 슬레이브로 동작하여 데이터를 주기적으로 수신
- **4개의 신호를 사용**
	1. **MOSI** (Master Output Slave Input)
	2. **MISO** (Master Input Slave Output)
	3. **SCK** (SPI Clock) → ==항상 **마스터**가 제공==
	4. **SS** (Slave Select)

### 2.14. I2C 모듈 (TWI: Two Wire Interface)
- **필립스社**에서 개발한 단거리용 **2선식** 직렬 통신 규격
- 2개의 라인(**SDA**, **SCL**)으로 최대 **400KHz** 데이터 전송속도의 **양방향** 직렬 통신
	- MCU와 주변 I/O 장치 간 통신, MCU와 MCU 간의 통신
- 마스터와 슬레이브 동작 지원
- ==**7비트 주소**로 최대 **128개**의 슬레이브와 통신==
- 슬레이브를 개별적으로 또는 모두를 동시에 호출하는 기능
- TWI 라인의 주소인식을 통해 MCU가 **슬립모드에서 해제**가 가능하다.
