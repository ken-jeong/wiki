## 요약
**User, Group, Role, Policy, Permission의 관계**
- **Policy**는 개별 기능에 대한 규칙이며, 이 Policy들이 모여 **Permission(권한)**이 된다.
- **User**는 개별 사용자(사람/애플리케이션)이고, **Group**은 여러 User를 묶은 집합이다.
- **Role**은 사용자나 AWS 서비스(Lambda 등)에 부여할 수 있는 역할(권한 세트)이다.

**콘솔 접근과 프로그래밍 방식 접근의 차이**
- **콘솔 접근(Management Console Access)**은 사람이 웹 브라우저로 전용 로그인 URL에 접속해 화면으로 조작하는 방식이고,
- **프로그래밍 방식 접근(Programmatic Access)**은 Access Key ID와 Secret Access Key를 발급받아 SDK나 API로 접근하는 방식이다.

**사용자에게 그룹 권한이 적용되는 과정**
- 그룹에 특정 정책(예: `AmazonEC2FullAccess`)을 연결하고 IAM 사용자를 그 그룹의 구성원으로 추가하면, 사용자는 그룹이 가진 모든 권한을 자동으로 **상속**받아 해당 리소스를 관리할 수 있게 된다.

## 1. IAM이란?
> [!summary] IAM (Identity and Access Management)
> AWS 서비스와 리소스에 대한 접근 권한(액세스)을 중앙에서 안전하게 관리하는 서비스

- **루트(Root) 계정 보호**: 모든 권한을 가진 Root 계정을 직접 노출하지 않고, 사용자나 애플리케이션에 **제한적인 권한**을 부여하고 싶을 때 사용한다.
- **접근 허용 및 거부**: IAM 사용자 및 그룹을 만들어 AWS 리소스에 대한 액세스를 세밀하게 허용하거나 거부할 수 있다.
- **최소 권한 원칙**: 사용자와 서비스에 꼭 필요한 권한만 부여하여 보안을 유지한다.
- **외부 API 연동**: 자격 증명 키(Key)를 발급하여 AWS 외부에서 API로 접근할 수 있다.
- **무료 서비스**: IAM 자체는 **추가 비용 없이 무료**로 제공된다. (사용자가 사용한 다른 AWS 서비스에 대해서만 요금이 부과된다.)

## 2. IAM 5대 핵심 개념
IAM은 **User, Group, Role, Policy, Permission**을 조합하여 권한을 관리한다.

| 개념 | 의미 및 역할 | 비고 / 예시 |
| :--- | :--- | :--- |
| **User (사용자)** | AWS 서비스를 사용하는 개별 주체 | 실제 **사람** 또는 **외부 애플리케이션** |
| **Group (그룹)** | 여러 **User들의 집합** | 부서/직무 단위로 묶어 일괄 권한 관리 (예: 개발팀, 운영팀) |
| **Policy (정책)** | 특정 AWS 요소의 특정 기능을 사용하기 위한 **정책(규칙)** | 예: `AmazonEC2ReadOnlyAccess`, `AmazonEC2FullAccess` |
| **Permission (권한)** | 하나 이상의 **Policy들의 집합** | 주체가 수행할 수 있는 허용/거부 범위 |
| **Role (역할)** | AWS의 작업과 리소스에 대한 액세스를 부여하는 **권한 세트** | 사람뿐만 아니라 **AWS 서비스(예: AWS Lambda)**가 다른 AWS 서비스에 접근할 때도 부여 |

> [!summary] 관계
> - 여러 개의 **Policy(정책)**가 모여 **Permission(권한)**을 구성한다.
> - 이 권한(Permission)을 **User(사용자)**, **Group(그룹)**, **Role(역할)**에 부여하여 AWS 리소스 접근을 제어한다.

## 3. IAM의 두 가지 접근 방식
IAM을 통해 AWS에 접근하는 방식은 크게 두 가지로 나뉜다.

### 3.1. Management Console Access (콘솔 접근)
- **접근 수단**: **웹 브라우저**를 통해 전용 `Console login link`로 접속
- **인증 정보**: **계정 ID**, **IAM 사용자 이름**, **암호(Password)**
- **주요 용도**: 사용자가 웹 콘솔(AWS Management Console)에 제한된 권한으로 로그인해야 할 때 사용

### 3.2. Programmatic Access (프로그래밍 방식 접근)
- **접근 수단**: **AWS SDK, CLI 등**을 이용해 AWS 서비스에 **API**로 접근
- **인증 정보**: **Access key ID** + **Secret access key**로 구성된 키 발급
- **주요 용도**: 외부 애플리케이션이나 코드에서 AWS 서비스를 호출할 때 일반적으로 많이 사용

## 4. 권한 작동 원리와 보안 관리
### 4.1. 정책에 따른 권한 제한
**`AmazonEC2ReadOnlyAccess` (읽기 전용 정책)**
- EC2 리소스를 **조회(읽기)**할 수만 있고, 생성하거나 변경할 수 없습니다.
- 이 권한만 가진 IAM 사용자가 EC2 인스턴스 생성을 시도하면 권한 부족(`RunInstances` 작업 권한 없음)으로 **실패**합니다.

**`AmazonEC2FullAccess` (전체 권한 정책)**
- EC2 리소스를 조회뿐만 아니라 **생성·변경·삭제(관리)**할 수 있는 모든 권한을 제공합니다.

### 4.2. 그룹을 통한 권한 상속
IAM 사용자는 **자신이 속한 그룹에 연결된 정책(Policy)의 권한을 모두 상속**받는다.

**작동 흐름**
1. 관리 권한이 있는 계정(루트 사용자 등)에서 IAM 그룹을 생성하고 권한 정책(예: `AmazonEC2FullAccess`)을 연결한다.
2. 해당 그룹에 IAM 사용자를 추가한다.
3. 그룹에 속한 IAM 사용자는 별도의 개별 설정 없이도 그룹의 전체 권한을 상속받아 이전에 실패했던 작업(EC2 인스턴스 생성 등)을 정상적으로 수행할 수 있다.

### 4.3. IAM 사용자 자격 증명 및 암호 보안
**자격 증명 CSV**
- IAM 사용자 생성 직후 제공되는 CSV 파일(사용자 이름, 초기 암호, 콘솔 로그인 URL 포함)은 **생성 직후 단 한 번만 다운로드**할 수 있으므로 안전하게 보관해야 한다.

**초기 암호 변경**
- 보안 강화를 위해 첫 로그인 시 자동 생성된 초기 암호로 인증한 뒤, 사용자가 직접 **새 암호(특수문자·숫자·대소문자 포함)**로 변경하도록 설정하는 것이 권장된다.
