## 요약
> [!summary] CloudWatch
> AWS 환경의 **지표·로그·이벤트**를 통합 관찰하여 **시각화**하고,
> 조건에 따른 **알람 발송 및 운영 자동화**를 지원하는 모니터링 서비스이다.

CloudWatch의 4가지 주요 기능
- 로그, 지표, 알람, 이벤트/자동 대응

이벤트 감지 후 실행할 수 있는 자동 대응 사례
- Lambda 호출, EC2 상태 변경, ASG 크기 조정

수집 간격 차이
- EC2 기본 모니터링(5분)
- 세부 모니터링(1분)

알람의 상태 변화
- `데이터 부족` → `정상` → `경보`

SNS 이메일 구독 확인 절차

## 1. CloudWatch란?
**CloudWatch**
- **AWS 리소스와 클라우드에서 실행되는 애플리케이션을 실시간으로 모니터링하는 서비스**이다.

**목적**
- 클라우드 환경에서 시시각각 발생하는 수많은 자원 상태와 이벤트를 체계적으로 수집·시각화하여,
- **장애 징후를 빠르게 파악하고 자동으로 대응**함으로써 시스템의 **고가용성(High Availability)**을 달성하도록 돕는다.

## 2. CloudWatch의 4대 주요 기능
### 2.1. 로그 모니터링 (Log Monitoring)
- 여러 소스에서 발생하는 로그 데이터를 **중앙 집중식으로 수집·검색·분석·모니터링**하는 기능

주요 예시 및 활용
- EC2 인스턴스, Lambda 함수, CloudTrail, 사용자 지정 로그 파일 수집
- 로그에서 도출된 인사이트로 운영 문제 해결

### 2.2. 지표 수집 및 모니터링 (Metrics)
- 다양한 AWS 서비스의 성능 지표를 수집하고 **그래프 및 사용자 정의 대시보드로 시각화**하는 기능

주요 예시 및 활용
- EC2의 CPU 사용률(`CPUUtilization`), 네트워크 입출력(I/O) 등 감시

### 2.3. 알람 (Alarms)
- 지정한 지표가 **사전에 정해진 조건(임곗값)을 벗어나면 알림을 발송**하거나 작업을 실행하는 기능

주요 예시 및 활용
- CPU 사용률이 5분간 80%를 초과하면 경보 발생 후 SNS로 이메일 발송

### 2.4. 이벤트 및 자동 대응 (Events & Automated Responses)
- AWS 리소스의 상태 변화(이벤트)를 감지하고, **사전 정의된 자동화 작업을 트리거**하는 기능

주요 예시 및 활용
- **AWS Lambda** 함수 호출
- **EC2 인스턴스** 상태 변경(시작/중지 등)
- **Auto Scaling 그룹(ASG)** 크기 자동 조정

## 3. EC2 모니터링 주기 비교 (기본 vs 세부)
EC2 인스턴스의 지표를 수집할 때, 필요한 관찰 주기에 따라 모니터링 방식을 선택할 수 있다.

| 구분 | 수집 간격 | 특징 |
| :--- | :---: | :--- |
| **기본 모니터링 (Basic Monitoring)** | **5분** 간격 | 기본으로 제공되는 모니터링 주기 |
| **세부 모니터링 (Detailed Monitoring)** | **1분** 간격 | 더 짧은 주기로 지표를 수집하여 **빠르게 이상 상황을 감지**해야 할 때 사용 |

## 4. CloudWatch 알람 관련 주요 개념
실습 과정에서 다룬 알람 설정 및 동작의 핵심 원리이다.

### 4.1. 알람 판단 기준 구성 요소
- **지표(Metric) 및 통계(Statistic)**: 감시할 대상 지표(예: `CPUUtilization`)와 계산 방식(예: **평균**, 최댓값 등)을 지정한다.
- **평가 기간(Period)**: 지표를 평가할 시간 단위(예: 5분 동안의 평균값)를 설정한다.
- **임곗값(Threshold)**: 알람이 울리는 기준선(예: 정적 임곗값 80% 이상)을 설정한다.

### 4.2. 알람의 3가지 상태
1. **데이터 부족 (`Insufficient data`)**: 알람을 막 생성하여 평가를 위한 지표 데이터가 아직 충분히 수집되지 않은 초기 상태이다.
2. **정상 (`OK`)**: 지표 데이터가 정상적으로 수집되었으며, 설정한 임곗값 범위 내에 있는 안전한 상태이다.
3. **경보 (`In alarm`)**: 수집된 지표가 지정한 임곗값 조건을 초과하여 이상이 감지된 상태이다.

### 4.3. 알림 전송과 Amazon SNS 연동
- **동작 방식**: 알람이 `경보(In alarm)` 상태로 전환될 때, **Amazon SNS(Simple Notification Service)의 주제(Topic)**를 통해 이메일 등으로 알림을 전송하거나 Auto Scaling/EC2 작업을 실행하도록 연결할 수 있다.

- **구독 승인 필수**: SNS 이메일 알림을 설정한 경우, 수신자가 이메일로 발송된 **구독 확인 링크(Confirm subscription)를 클릭해 승인(`확인됨` 상태)**해야만 정상적으로 경보 알림 메일을 받을 수 있다.
