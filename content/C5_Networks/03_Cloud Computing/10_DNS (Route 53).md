> [!tip] DNS 및 트래픽 라우팅
> 도메인 이름을 내부 및 외부 리소스와 연결한다.
> 라우팅 정책에 따라 트래픽을 적절한 대상으로 전달한다.
> - AWS **Route 53**
> - NCP **Global DNS**, Global Traffic Manager (GTM)

## 요약
==DNS가 필요한 이유==
- 외우기 어려운 숫자(IP 주소) 대신 기억하기 쉬운 이름(도메인)으로 서버에 접속

==호스팅 영역==
- 도메인 단위로 레코드들을 담아두는 컨테이너 (관리 공간)
- ==레코드==: 도메인과 IP 주소(또는 라우팅 대상)를 실제로 매핑한 개별 설정 정보 (이름, 유형, 값 등으로 연결 정보를 표현)
	- A: IPv4 주소 매핑
	- AAAA: IPv6 주소 매핑
	- CNAME: 다른 도메인 이름 (별칭) 연결
	- MX: 메일 서버 지정
	- NS: 담당 네임서버 정보 (호스팅 영역 생성 시 자동 생성)
	- SOA: 도메인의 기본 관리 권한 정보 (호스팅 영역 생성 시 자동 생성)

라우팅 정책
- 응답할 대상을 선택하는 기준이다.
1. 지연 시간 기반 라우팅 (가장 빠른 응답 속도)
2. 가중치 기반 라우팅 (지정한 트래픽 비율)
3. 지역 기반 라우팅 (사용자의 지리적 위치)

## 1. DNS의 이해
### 1.1. DNS란?
**DNS** (Domain Name System)
- 사람이 기억하기 쉬운 **도메인 이름을 서버의 IP 주소로 변환**해 주는 시스템이다.

**필요한 이유** (전화번호부 비유)
- 스마트폰에서 전화번호(`010-1234-1111`)를 일일이 외우는 대신 **이름(연락처)**을 눌러 전화를 거는 것과 같다.
- 서버에 접속하려면 숫자로 된 긴 IP 주소를 알아야 하지만 외우기 어렵기 때문에, 도메인 이름(`google.com` 등)으로 접속하면 DNS가 이를 실제 IP 주소로 변환해 서버에 연결해 준다.

### 1.2. DNS 레코드와 매핑
**레코드**
- 도메인 이름과 대상 IP 주소가 연결(매핑)된 **정보 한 건**을 의미한다.

**동작 과정**
- 사용자가 도메인 이름으로 접속을 시도하면
- → DNS 테이블에서 해당 레코드를 조회하여
- → 매핑된 IP 주소의 대상 서버로 접속한다.

## 2. Amazon Route 53 핵심 개념
### 2.1. Route 53 소개
**클라우드 관리형 DNS**
- AWS에서 제공하는 DNS 서비스로, AWS 내부 인프라(**EC2 인스턴스, ELB 로드 밸런서, S3 버킷, CloudFront 배포** 등)뿐만 아니라 AWS 외부 인프라로도 트래픽을 쉽게 라우팅할 수 있다.

### 2.2. 호스팅 영역과 레코드
**호스팅 영역** (Hosted Zone)
- 한 도메인의 DNS 설정과 레코드들을 모아 관리하는 **컨테이너**(도메인별 관리 공간)
- 호스팅 영역의 이름은 해당 도메인 이름과 동일함
- **퍼블릭 호스팅 영역**: **인터넷**에서 도메인 트래픽을 라우팅할 때 사용
- **프라이빗 호스팅 영역**: **Amazon VPC 내부**에서 트래픽을 라우팅할 때 사용

**레코드** (Record)
- 호스팅 영역 안에 저장되며, 특정 도메인(`example.com`)이나 하위 도메인(`apex.example.com`)의 **트래픽 라우팅 방식과 연결된 IP 정보**를 담는 단위
- 한 호스팅 영역 안에 여러 개의 DNS 레코드를 저장 및 관리한다.

### 2.3. Route 53 주요 용어
- **DNS 쿼리 (DNS Query)**: 도메인 이름을 IP 주소로 변환해 달라고 요청하는 조회 작업이다.
- **DNS 장애 조치 (Failover)**: Route 53에 연결된 서버나 ELB에 장애가 발생했을 때, 상태 확인을 통해 정상 작동하는 **다른 대체 위치로 트래픽을 라우팅**하는 기능이다.

## 3. Route 53 대표 레코드 유형
호스팅 영역에서 목적에 따라 사용하는 주요 레코드 유형은 다음과 같다.

| 레코드 유형 | 전체 명칭 | 용도 및 설명 | 비고 |
| :---: | :--- | :--- | :--- |
| **A** | Address | 도메인 이름을 **IPv4 주소**에 매핑하는 가장 기본적인 레코드 | 사용자 생성 |
| **AAAA** | Address | 도메인 이름을 **IPv6 주소**에 매핑하는 레코드 | 사용자 생성 |
| **CNAME** | Canonical Name | **별칭 레코드**. 현재 도메인 이름에 대한 쿼리를 **다른 도메인 또는 하위 도메인 이름**으로 연결<br>*(예: `docs.example.com` → `documents.example.com`)* | 사용자 생성 |
| **MX** | Mail eXchange | 이메일을 전달하기 위해 **메일 서버를 지정**하는 레코드 | 사용자 생성 |
| **NS** | Name Server | 도메인의 **네임서버 주소**를 담고 있는 레코드 | **자동 생성** |
| **SOA** | Start of Authority | **권한 시작 레코드**. 도메인에 대한 기본 DNS 정보를 식별하는 레코드 | **자동 생성** |

> [!caution] NS 및 SOA 레코드 주의사항 (중요)
> 1. **임의 변경 금지**: `NS`와 `SOA` 레코드는 호스팅 영역을 생성할 때 **Route 53이 자동으로 생성**하는 핵심 정보이므로 함부로 변경하거나 삭제하면 안 된다.
> 2. **호스팅 영역 삭제 조건**: 호스팅 영역을 삭제하려면 사용자가 직접 추가한 레코드(A 레코드 등)를 **먼저 모두 삭제**하고, 기본 생성된 **`NS`와 `SOA` 레코드만 남아 있는 상태**여야 영역 삭제가 가능하다.

## 4. Route 53 라우팅 방식 (라우팅 정책)
Route 53은 트래픽을 어떤 기준으로 대상 서버에 보낼지 결정하는 여러 라우팅 정책을 제공한다.

### 4.1. 지연 시간 기반 라우팅
> Latency based Routing

- 선택 기준: **응답 속도** (지연 시간, Latency)
- 클라이언트 기준으로 **지연 시간(ms)이 가장 낮은(가장 빠른) 리전**의 IP 주소로 라우팅
*(예: 46ms, 23ms, 12ms 중 **12ms** 리전 선택)*
- **활용**: 사용자 응답 속도 및 성능 최적화

### 4.2. 가중치 기반 라우팅
> Weighted based Routing

- 선택 기준: **설정 비율** (가중치, Weight)
- 각 IP 주소나 ELB DNS 주소에 **가중치(비율)**를 부여하고 그 비율만큼 트래픽을 분배
*(예: A 리전에 **70**, B 리전에 **30** 비율로 요청 분배)*
- **활용**: 트래픽 분산, 신규 서비스 단계적 전환(테스트)

### 4.3. 지역 기반 라우팅
> Geo Routing

- 선택 기준: **사용자 위치** (지리적 위치)
- 클라이언트가 **위치한 지역(국가/대륙 등)**에 따라 각기 다른 지정된 IP 주소(리전)로 라우팅
- **활용**: 지역 맞춤형 콘텐츠 제공 및 국가별 규정 대응

## 5. 알아두면 유용한 도구: `dig` 명령어
**`dig` 명령어**
- Linux나 macOS 터미널 환경에서 특정 도메인의 **DNS 응답 결과(매핑된 IP 주소, TTL 등)와 DNS 서버 정보를 조회**할 때 사용하는 명령어이다.

```sh
dig google.com
```
