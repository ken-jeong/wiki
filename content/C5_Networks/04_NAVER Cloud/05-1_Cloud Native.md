> [!summary] 핵심 요약
> - **클라우드 네이티브**는 컨테이너·MSA·불변 인프라·선언형 API·서비스 메쉬를 활용해 클라우드의 유연성과 확장성을 극대화하는 개발·운영 방법론이다.
> - **컨테이너**는 호스트 OS 커널을 공유해 VM보다 가볍고 빠르게 실행되며, Docker 이미지의 Stateless·계층 구조, 레지스트리, **CI/CD**를 통해 지속적이고 일관된 배포를 자동화한다.

## 1. 클라우드 네이티브 (Cloud Native)
### 1.1. 개념과 CNCF 5대 요소
- **정의**: 클라우드 컴퓨팅의 장점(유연성, 확장성, 탄력성)을 최대한 활용하여 애플리케이션을 설계·개발·운영하는 방법론이다.
- **CNCF 5대 핵심 요소**: **컨테이너(Container)**, **서비스 메쉬(Service Mesh)**, **MSA(Microservices Architecture)**, **불변 인프라(Immutable Infrastructure)**, **선언형 API(Declarative API)**

### 1.2. 핵심 아키텍처와 가상화 비교
- **MSA (Microservices Architecture)**: 하나의 거대한 애플리케이션을 독립적으로 배포·확장 가능한 작은 기능 단위로 분해하여 구축하는 아키텍처이다.
- **컨테이너화 (Containerization)**: MSA로 나뉜 애플리케이션을 코드와 종속성째 패키징해 일관되게 배포·실행하는 기술이다.

| 비교 항목 | 컨테이너 (Container) | 가상 머신 (VM) |
| :--- | :--- | :--- |
| **OS 구조** | 호스트 OS 커널을 공유 | 하이퍼바이저 위에 독립된 전체 Guest OS 포함 |
| **크기 · 자원 효율** | 경량화(최소한의 바이너리·라이브러리만 포함) | 전체 OS 포함으로 무겁고 리소스 소모가 큼 |
| **기동 속도** | 빠른 시작 및 종료 | OS 부팅이 필요해 상대적으로 느림 |

- **장점**: 개발·릴리스 속도 향상, 인프라 비용 절감, 운영 관리 용이성
- **단점**: 특정 클라우드 벤더 종속(Vendor Lock-in) 우려, 높은 기술 학습 곡선

## 2. 컨테이너, Docker와 CI/CD
*(Docker 상세 명령어와 활용 개념은 [[06_Docker]], 대규모 컨테이너 오케스트레이션은 [[05-2_K8s (NCP NKS)]] 참고)*

- **컨테이너 유형**:
	- **시스템 컨테이너**: 기존 OS 위에 OS 환경 자체를 컨테이너 형식으로 운영
	- **애플리케이션 컨테이너**: 단일 애플리케이션 실행이 목적 (하나의 OS 위에서 3-Tier 구성 등 가능)
- **Docker 이미지 특징**:
	- **Stateless**: 실행 시 변경되는 상태 값을 이미지 자체에 저장하지 않음
	- **계층(Layer) 구조**: 바이너리와 라이브러리가 계층적으로 쌓이며 JSON 형태 메타데이터로 관리됨
- **이미지 레지스트리 (Registry)**:
	- **Public**: Docker Hub 등 인터넷을 통해 공개 공유
	- **Private**: OS 설정·미들웨어 정보 등 민감 정보 보호를 위해 기업 내부에 별도 구축
	- **Lifecycle**: `Pull`(다운로드) → `Push`(업로드) → `Delete`(용량 관리)
- **CI / CD (지속적 통합 / 지속적 배포)**:
	- **CI (Continuous Integration)**: 코드 변경 사항을 자주 통합·검증
	- **CD (Continuous Deployment)**: 검증된 변경 사항을 운영 환경에 자동 배포하여 짧은 주기로 서비스를 개선
