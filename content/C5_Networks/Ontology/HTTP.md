## 1. 하이퍼텍스트 (Hypertext)
- 링크를 통해 서로 연결된 비순차적 텍스트

## 2. HTML (HyperText Markup Language)
- 팀 버너스리가 웹을 창시하면서 하이퍼텍스트를 웹 브라우저에서 볼 수 있도록 만든 마크업 언어

## 3. HTTP (HyperText Transfer Protocol)
- **클라이언트**(웹 브라우저)와 **서버**(웹 서버)가
- 인터넷에서 **하이퍼텍스트**(HTML)를 주고받기 위해 사용하는
- **애플리케이션 레벨**의 네트워크 프로토콜

### 특징
1. **클라이언트-서버 모델 (Client-Server)**
	- **클라이언트**(브라우저 프로그램)가 웹 객체를 [[HTTP 요청]]하면,
	- **서버**(웹 서버 프로그램)는 요청을 처리한 뒤 [[HTTP 응답]]을 반환하는 단방향 구조이다.

2. **비연결성 (Connectionless)**
	- 클라이언트·서버가 한 번의 요청·응답을 주고받으면 TCP 연결을 끊는다.
	- **장점**: 불필요한 연결 유지를 줄여 서버 자원을 아낄 수 있다.
	- **단점**: 매 요청마다 TCP 3-Way Handshake를 다시 해야 하므로 네트워크 오버헤드가 발생한다.
	- **보완**: HTTP/1.1부터 Keep-Alive(지속 연결) 헤더를 기본으로 사용하여 일정 시간 동안 연결을 재사용한다.

3. **무상태성 (Stateless)**
	- 비연결성으로 인해 서버가 클라이언트 이전 요청의 상태 정보를 저장하지 않는다.
	- **장점**
		- 프로토콜의 복잡도가 낮고, 서버에 부하가 적다.
		- 서버 확장이 용이하고(스케일 아웃), 특정 서버가 다운되어도 다른 서버가 대체하기 쉽다.
	- **보완**
		- 상태를 유지해야 하는 서비스(로그인 등)는 **쿠키(Cookie), 세션(Session), 토큰(JWT)** 등을 사용해 상태를 관리한다.

4. **범용성**
	- 현재는 HTML 외에도 이미지, 동영상, JSON 등 웹에서 사용되는 거의 모든 데이터를 전송한다.

### 동작 과정
> 데이터 요청 → 데이터 응답 → 연결 종료

1. **TCP 프로토콜**을 사용한다.
2. 클라이언트는 소켓을 열고 **80번 포트**를 이용하여 웹 서버와 TCP 연결을 시도한다.
3. 서버는 클라이언트의 연결 요청을 수용한다.
4. HTTP 메시지(URL, HTML 파일 등)가 웹 서버와 웹 브라우저 간에 송수신된다.
5. 전송 후 TCP 연결을 종료한다.
