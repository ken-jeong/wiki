## TCP/IP
> Transmission Control Protocol / Internet Protocol

- 컴퓨터와 컴퓨터가 인터넷상에서 원활하게 데이터를 주고받을 수 있도록 정의한 통신 규약(프로토콜)들의 묶음이다.
- 가장 핵심적인 역할을 하는 **TCP**(전송 제어)와 **IP**(패킷 라우팅)의 이름을 따서 부르지만, 실제로는 이 둘만 의미하는 것이 아니다. 인터넷 통신에 쓰이는 수많은 프로토콜 전체를 포괄하는 명칭(Internet Protocol Suite)이다.

---

- 서로 다른 통신망에서 서로 다른 통신 프로토콜을 이용하더라도 상호 통신이 가능하도록 개발되었다.
- 실제 인터넷 통신 규약으로 자리 잡은 실무 구현 중심의 모델이다. (RFC 1122 등 기반) 사실상의 표준(De Facto Standard) 통신 프로토콜이다.
- 1983년, 미국 국방부 ARPANET의 공식 표준 프로토콜로 채택되었다.

## TCP/IP 4계층 모델
> 4-Layer Model
> Original TCP/IP Model

- TCP/IP 프로토콜들이 데이터 전송 시 어떤 순서와 역할을 가지고 동작하는지 4개의 층(Layer)으로 논리적으로 나누어 놓은 개념적 구조이다.

### L4. 응용 계층 (Application Layer)
- 특정 서비스를 제공한다.

> 세션 유지나 데이터 표현(암호화/인코딩)을 애플리케이션 레벨에서 처리하므로, 응용 계층 하나로 통합한다.

### L3. 전송 계층 (Transport Layer)
> 응용 계층의 데이터를 받아, 네트워크를 통해 안정적이고 효율적으로 상대 컴퓨터에 전달하는 역할을 수행하는 계층이다.

### L2. 인터넷 계층 (Internet Layer)
- 여러 네트워크에 걸쳐 데이터를 전송하는 핵심적인 역할을 수행한다.
- 논리적 주소 지정, 패킷화, 패킷 전달 및 라우팅, 단편화 및 재조립

### L1. 네트워크 액세스 계층 (Network Access Layer)
- 노드 간의 신뢰성 있는 데이터 전송을 담당한다.
- 알맞은 하드웨어로 데이터가 전달되도록 MAC 주소를 처리하고, 데이터 패킷을 전기신호로 변환하여 선로로 통하여 전달할 수 있도록 지원한다.

데이터링크 계층
- PPP, Ethernet(유선 연결), **Wi-Fi(802.11; 무선 연결)**, Token Ring, FDDI
- 인터페이스 카드: **MAC**, NIC 드라이버, L2 스위치, 브리지

물리 계층
- 전파/전기 신호, 케이블(UTP, 광케이블 등), 커넥터(RJ-45 등), 리피터, 허브

## TCP/IP 5계층 모델
> Modern / Updated TCP/IP Model

최근 전산/네트워크 전공 서적과 업계에서 가장 널리 채택하는 모델이다.

*왜 5계층이 등장했는가?*
- TCP/IP 4계층의 '네트워크 액세스(링크) 계층'은 하드웨어 신호(물리)와 프레임/MAC 주소 제어(데이터 링크)가 혼재되어 있어 구조적 분석이 어렵다.
- 따라서 상위(응용) 계층은 소프트웨어 영역으로 묶어두되, 하위 물리(L1)와 데이터 링크(L2)는 기술적 특성이 완전히 다르므로 OSI처럼 분리하여 5개 계층으로 설명한다.

### L5. 응용 계층 (Application Layer)
#### 응용 계층의 프로토콜
> TCP 또는 UDP를 기반으로 동작하며, 지정된 포트 번호를 사용한다.

TCP를 사용하는 프로토콜(포트 번호)
- **FTP**(20/21): 파일
- **SSH**(22), Telnet(23): 원격 접속
- **SMTP**(25), POP3(110/995), IMAP(143): 이메일
- **HTTP**(80), HTTPS(443): 웹

TCP, UDP를 모두 사용하는 프로토콜(포트 번호)
- [[DNS]](53)

UDP를 사용하는 프로토콜(포트 번호)
- BOOTP/DHCP(67/68)
- TFTP(69)
- SNMP(161/162)
- RIP(520): 홉 카운트 라우팅 프로토콜

### L4. 전송 계층 (Transport Layer)
- ==Process-to-Process==
	- 포트 번호(Port Number)로 식별한다.

#### 전송 계층의 프로토콜
**TCP** (전송 제어 프로토콜; IP 프로토콜 번호 `6`)
- **연결 지향형**: 데이터를 보내기 전 3-way handshaking 과정으로 연결을 먼저 맺는다.
- **느린 속도**: 확인 절차가 많아 UDP보다 속도가 느리다.
- **높은 신뢰성**: 데이터가 빠짐없이 순서대로 정확히 전달되도록 보장한다. 중간에 유실된 데이터가 있으면 다시 보낸다.
- **흐름 및 혼잡 제어**: 네트워크 상황에 맞춰 데이터 전송 속도를 조절한다.
- 주요 용도: 웹 서핑(HTTP), 이메일, 파일 전송 등 정확성이 중요한 서비스

**UDP** (사용자 데이터그램 프로토콜; IP 프로토콜 번호 `17`)
- **비연결형**: 연결 설정 과정 없이 곧바로 데이터를 전송한다.
- **빠른 속도**: 제어 과정이 없어 오버헤드가 적고 전송 속도가 매우 빠르다.
- **낮은 신뢰성**: 데이터가 유실되거나 순서가 바뀔 수 있으며, 도착 여부를 확인하지 않는다.
- 주요 용도: 실시간 음성 통화(VoIP), 실시간 스트리밍, 온라인 게임 등 속도가 더 중요한 서비스

### L3. 네트워크 계층 (Network Layer)
- ==Host-to-Host==
	- IP 주소로 식별한다.

**IP 기준 상위 프로토콜** (프로토콜 번호)
- **ICMP**(Internet Control Message Protocol, 인터넷 제어 메시지 프로토콜; `1`)
	- `ping`은 ICMP 요청을 보내고 응답을 통해 네트워크 상태를 진단한다.
	- `traceroute`는 TTL을 1씩 늘려가며 보내 ICMP로 오류 보고를 받는다.
- IGMP(2)
- IGRP(88)
- OSPF(89)

**이더넷 기준 상위 프로토콜** (EtherType)
- **IPv4**(`0x0800`)
- ARP(`0x0806`): IP 주소 -> MAC 주소
- RARP(`0x8035`): MAC 주소 -> IP 주소
- **IPv6**(`0x86DD`)

### L2. 데이터 링크 계층 (Data Link Layer)

### L1. 물리 계층 (Physical Layer)

> [!tip] 설계 과제와의 연결
> 패킷 캡처 프로그램에서는 이 값들을 그대로 사용한다.
> 이더넷 프레임의 타입 필드(0x0800 = IP)로 상위 프로토콜을 판별하고,
