서로 다른 애플리케이션 프로그램들이
정해진 약속(규격)에 따라
안전하고 편리하게 데이터와 기능을 주고받을 수 있도록 해주는
소프트웨어 간의 통로이다.

## 1. API (Application Programming Interface)
서로 다른 소프트웨어(애플리케이션) 프로그램들이 **데이터를 주고받고 소통할 수 있도록 돕는 매개체(규칙과 도구)**이다.

Application
- 사용자의 사용을 목적으로 만들어진 컴퓨터 프로그램, 즉 응용 소프트웨어

Programming Interface
- 그 응용 프로그램을 다루기 위한 인터페이스

## 2. API 동작
1. **요청** (Request): 앱(클라이언트)이 API 규격에 맞춰 서버에 특정 데이터나 동작을 요청한다. (예: "오늘 서울 날씨 알려줘")
2. **처리**: 서버가 요청을 검증하고 필요한 데이터를 가공한다.
3. **응답** (Response): API가 서버로부터 결과 데이터를 받아 앱에 전달한다. (보통 웹에서는 **JSON**이나 **XML** 같은 표준화된 텍스트 형식으로 주고받는다.)

## 3. API의 종류
### ① 공개 범위에 따른 분류
- **오픈 API (Open API / Public API)**: 누구나 사용할 수 있도록 외부에 공개된 API (예: 기상청 공공데이터, 공공 버스 도착 정보 등).
- **프라이빗 API (Private API)**: 특정 기업 내부 시스템 간의 연동을 위해서만 사용되며 외부에 공개되지 않는 API.
- **파트너 API (Partner API)**: 비즈니스 제휴를 맺은 특정 파트너사에게만 제공되는 API.

### ② 기술/통신 방식에 따른 분류
- **REST API**: 현재 웹/모바일 환경에서 가장 널리 쓰이는 표준 방식이다. HTTP 메서드(GET, POST, PUT, DELETE 등)를 사용하여 직관적이다.
- **GraphQL**: 페이스북(메타)이 개발한 방식으로, 클라이언트가 필요한 데이터 필드만 콕 집어서 요청할 수 있는 효율적인 방식이다.
- **SOAP**: 보안성과 규격화가 매우 엄격해 전통적인 금융권이나 기업용 시스템에서 주로 쓰인다.

## 4. API를 사용하는 이유 (장점)
1. **개발 효율성 향상**: 지도, 결제, 본인인증 등을 매번 새로 개발할 필요 없이 이미 잘 만들어진 API를 붙여 빠르게 서비스를 구현할 수 있다.
2. **보안성**: 데이터베이스의 원본 구조나 핵심 소스코드를 외부에 직접 노출하지 않고, 허용된 데이터만 선별하여 안전하게 제공할 수 있다.
3. **유지보수와 확장성**: 각 시스템이 분리되어 통신하므로, 한쪽 시스템의 내부 구조가 바뀌더라도 API 규격만 유지되면 다른 서비스에 영향을 주지 않는다.

## 5. API 관련 도구
API를 설계, 개발, 테스트, 문서화, 모니터링할 때 사용하는 **대표적인 API 관련 도구(Tools)**들을 단계별·용도별로 정리한다.

### 5.1. API 테스트 및 호출 도구 (API Clients)
API가 의도한 대로 동작하는지 직접 요청을 보내보고 응답을 확인하는 도구이다.

- ==Postman==
	- 전 세계 수많은 개발자가 기본으로 사용하는 API 개발/테스트 GUI 플랫폼이다.
	- 요청(GET, POST 등) 전송, 환경변수 관리, 자동화 테스트 스크립트 작성, 협업 워크스페이스 제공
- **Insomnia**
	- **설명**: Postman보다 가볍고 심플한 인터페이스를 선호하는 개발자들에게 인기 있는 도구이다.
	- **특징**: REST뿐만 아니라 GraphQL, gRPC 테스트 환경이 깔끔하게 잘 지원된다.
- Hoppscotch / ==Bruno==
	- **설명**: 최근 주목받는 가볍고 투명한 오픈소스 기반 API 클라이언트이다.
	- **특징**: Bruno는 로컬 Git 저장소에 API 요청 정보를 일반 파일 형태로 직접 저장하여 버전 관리가 매우 편리하다.
- **cURL (CLI 기반)**
	- **설명**: 터미널(명령 프롬프트)에서 바로 명령어를 입력해 API를 호출할 수 있는 가장 기본적인 커맨드라인 도구이다.

### 5.2. API 설계 및 문서화 도구 (Design & Documentation)
"이 API는 어떤 주소로, 어떤 형식의 데이터를 주고받아야 하는가"를 공유하고 문서화하는 도구이다.

- ==Swagger (OpenAPI)==
	- 사실상 업계 표준인 API 명세 및 문서화 프레임워크이다.
	- 코드 기반으로 문서를 자동 생성할 수 있고, 웹 브라우저 상에서 버튼을 눌러 API를 즉시 테스트해볼 수 있는 대화형 UI를 제공한다.
- **Redoc**
	- **설명**: OpenAPI 명세(YAML/JSON)를 깔끔하고 가독성 좋은 3단 반응형 웹 문서로 변환해 주는 도구이다.
- **Stoplight**
	- **설명**: 코딩 전에 API를 먼저 설계(API Design First)하고 문서를 만들 수 있는 시각적 편집 도구이다.

### 5.3. 모킹(Mocking) 도구: 가짜 API 만들기
백엔드 API가 아직 완성되지 않았을 때, 프론트엔드 개발자가 가짜(Mock) 데이터를 받아와 화면 개발을 먼저 진행할 수 있도록 돕는 도구이다.

- **JSON Server**
	- **설명**: JSON 파일 하나만 작성해 두면 1분 만에 임시 REST API 서버를 띄워주는 간단한 도구이다.
- **MSW (Mock Service Worker)**
	- **설명**: 웹 브라우저의 서비스 워커를 이용해 네트워크 요청을 가로채서 가짜 데이터를 반환해 주는 프론트엔드용 모킹 라이브러리이다.
- **WireMock**
	- **설명**: 통합 테스트나 마이크로서비스 환경에서 외부 API 의존성을 격리하고 시뮬레이션할 때 많이 쓰는 강력한 도구이다.

### 5.4. API 게이트웨이 및 관리 도구 (API Gateway & APIM)
수많은 API 요청의 진입로 역할을 하며, 인증/인가, 트래픽 제한(Rate Limiting), 라우팅을 총괄하는 도구이다.

- **Kong Gateway**
	- **설명**: 매우 빠르고 가벼운 오픈소스 기반 클라우드 네이티브 API 게이트웨이다.
- **AWS API Gateway**
	- **설명**: 아마존 웹 서비스(AWS)의 완전관리형 서비스로, 서버리스(Lambda 등) 환경과 결합하여 트래픽을 처리하기에 적합하다.
- **Apigee (Google Cloud)**
	- **설명**: 대규모 엔터프라이즈 환경에서 API 분석, 보안, 수익화(과금 체계)까지 관리할 수 있는 고급 플랫폼이다.

### 5.5. API 부하 및 성능 테스트 도구 (Load Testing)
수만 명의 사용자가 동시에 API를 호출했을 때 서버가 버틸 수 있는지 검증하는 도구이다.

- **k6 (Grafana k6)**
	- **설명**: JavaScript 코드로 부하 테스트 시나리오를 작성할 수 있는 현대적이고 가벼운 부하 테스트 도구이다.
- **Apache JMeter**
	- **설명**: 오랫동안 사용되어 온 전통적이고 검증된 성능 테스트 툴로, 복잡한 시나리오 구성에 강점이 있다.
