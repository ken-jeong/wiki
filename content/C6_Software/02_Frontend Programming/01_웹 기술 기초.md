## 1. 인터넷과 웹의 역사
- cf. [[10_Networks#1.2. 네트워크의 역사]]

### 1.1. 네트워크와 TCP/IP
**네트워크**
- 컴퓨터를 연결하는 망의 개념

[[TCP-IP|TCP/IP 4계층 모델]]

**TCP/IP**
- 컴퓨터 간에 통신할 수 있도록 만든 인터넷 표준 프로토콜
- 하드웨어, 운영체제, 접속 매체에 관계없이 데이터 통신할 수 있는 **개방형 프로토콜**
- 1982년 인터넷의 표준 프로토콜로 제정

### 1.2. 인터넷의 탄생과 발전
[[인터넷]]

### 1.3. World Wide Web
**World Wide Web (WWW)**
- 1989년 유럽 원자핵 연구소(CERN)의 팀 버너스리가 개발
- 하이퍼텍스트를 통해 정보를 전달·공유하는 서비스
- HTML로 콘텐츠를 작성하고, HTTP 프로토콜로 TCP/IP 네트워크에서 서비스 제공

**3가지 표준 기술**
- **HTML**(HyperText Markup Language): 인터넷 상의 정보 표현 언어
- [[HTTP]]: 웹 페이지 정보 전송 프로토콜
- **URL**(Uniform Resource Locator): 표준 주소 표기 방식

## 2. 웹의 동작 원리
### 2.1. 클라이언트-서버 모델
소프트웨어 아키텍처: 클라이언트-서버 모델
- (자원을 관리하는 서버 vs 서비스를 요청하는 클라이언트)

*상세 설명*
- 클라이언트와 공통 서비스를 제공하는 서버 시스템들과 상호 작용하는 구조
- 서버: 자원을 관리하며 클라이언트가 요청하는 기능이나 자원을 제공
- 아파치 톰캣(Apache Tomcat) 웹 서버 프로그램
- 클라이언트: 서버가 제공하는 서비스를 요청(호출)하는 서브시스템
- 크롬(Chrome)이나 사파리(Safari)와 같은 웹 브라우저

### 2.2. HTTP와 WWW 동작 과정
**WWW 동작 원리**
- 클라이언트(웹 브라우저)가 웹 서버에 **HTTP 프로토콜**로 요청을 보내면,
- 서버가 HTML을 응답하고 브라우저가 이를 해석하여 화면에 표시한다.
- *HTTP: 웹 서버와 웹 브라우저 사이에 하이퍼텍스트 문서를 위한 통신 규약*

### 2.3. URL과 도메인 이름
**URL**
- 인터넷에 있는 자원(resource)의 위치를 나타내는 표준 규약
- 구성: `프로토콜://호스트(도메인):포트/경로`
- 예: `http://localhost:8080/board` → Protocol(`http://`), Host(`localhost`), Port(`:8080`), Path(`/board`)
- **Origin** = 프로토콜 + 호스트 + 포트

## 3. 웹 브라우저
- cf. [[10_Networks#7.2. 웹 브라우저와 웹 서버]]

### 3.1. 브라우저의 역사와 현황
**역사**
- 1993년 GUI 방식의 **모자익**(Mosaic)
- 1994년 상업용 **넷스케이프**(Netscape)
- 1995년 MS가 Windows 95에 **인터넷 익스플로러**를 통합 판매

**현황** (2000년대 중반 이후 점유율 경쟁)
- 구글 **크롬**(Chrome)이 지속적·압도적 우위
- 애플 기기에서는 **사파리**(Safari)가 꾸준히 높은 점유율
- 엣지(Edge)와 파이어폭스(Firefox)는 5% 미만

### 3.2. 주요 브라우저
- **Chrome**: 2008년 출시, 오픈소스, 웹 표준 호환성 우수, 안드로이드 호환으로 점유율 선두
- **Safari**: 2003년 애플이 매킨토시용으로 개발, 아이폰·아이패드 등 애플 기기에서 사용
- **Firefox**: 2004년 비영리 모질라 재단이 1.0 발표, 자유 소프트웨어, 다양한 OS 지원, 표준 준수율 높음

### 3.3. 개발자 도구
- HTML/CSS/JS 코드의 문제를 브라우저에서 바로 확인하고 수정하는 기능
- 실행 방법: `F12` / `우클릭 → 검사` / `도구 더보기 → 개발자 도구`

## 4. 웹 프로그래밍 기술
### 4.1. 프론트엔드와 백엔드
- *프로그램은 서버에서 실행되고, 실행 결과만 컴퓨터의 브라우저를 통해 보여짐*
- **백엔드(Server)**: 서버를 구성하고 서비스를 제공 (웹 서버 소프트웨어, 프레임워크, DB)
	- *cf. Back-end Framework*: JSP, Spring Framework, Python(Django, Flask, FastAPI), Nest.js
- **프론트엔드(Client)**: 클라이언트 중심 프로그래밍 - 화면 구성(HTML), 스타일(CSS), 동적 처리(JavaScript)

### 4.2. 프론트엔드 기본 언어
> 기본적으로 브라우저에 의해 처리되는 요소이다.

1. **HTML** (HyperText Markup Language) → [[02_HTML5]]
	- ==문서의 구조를 정의하는 마크업 언어==
	- ==계층적인 태그로 요소를 표시==
2. **CSS** (Cascading Style Sheet) → [[03_CSS3 Style Sheet]]
	- HTML에서 디자인 요소(색상, 크기, 정렬)를 분리하여 시각적 요소 정의
	- CSS 프레임워크: 부트스트랩, Tailwind CSS
3. **JavaScript** → [[04_JavaScript 기초]]
	- 사용자 상호작용 및 동적 처리를 위한 스크립트 언어
	- (최신 버전 ES6+ 활용)
4. **TypeScript**
	- 마이크로소프트가 구현한 JavaScript의 **슈퍼셋**(superset) 언어

### 4.3. 마크업 언어와 HTML
#### (1) 마크업 언어
- 문서의 속성을 설정하기 위한 마크업을 태그의 형태로 표시
- **SGML**(Standard Generalized Markup Language)
	- 다양한 형식의 전자문서들의 구조와 내용을 기술하는 국제표준(1986, ISO)
- **HTML**(==HyperText== Markup Language)
	- SGML로 정의된 문서 형식으로 주로 웹 문서 작성에 사용
- **XML**(eXtensible Markup Language)
	- 문서나 자료의 교환이 필요한 경우 새로운 언어가 필요

#### (2) HTML 역사
- SGML(1986) → HTML(1991) → HTML 2.0(1995) → HTML 4.0(1997, Dynamic HTML)
- XML(1998) → XHTML 1.0(2000) → **HTML5(2014)**
- CSS1(1996, JavaScript와 함께) → CSS2(1998) → CSS3

#### (3) HTML5 특징
- 추가된 태그
	- 시맨틱 요소: `<header>`, `<nav>`, `<main>`, `<section>`, `<aside>`, `<article>`, `<footer>`, `<figure>`
	- 멀티미디어 요소: `<video>`, `<audio>`
	- 그래픽 요소: `<canvas>`, `<svg>`
- 오프라인 웹 애플리케이션: 네트워크 연결 없이도 실행 가능
- 드래그 앤 드롭(Drag-and-drop)
- 웹 스토리지(Web Storage): 쿠키를 대체하는 웹 저장소
- 위치 정보(Geolocation): 지도 기능
- 웹 SQL 데이터베이스, 파일 API(업로드·관리)
- 웹소켓(WebSocket): 서버-브라우저 간 **양방향 통신**
- 웹 워커(Web Worker): 독립적으로 작업을 처리하는 스레드

### 4.4. JavaScript와 ECMAScript
#### (1) JavaScript 역사
- 넷스케이프의 **브랜든 아이크**가 **라이브스크립트**(LiveScript)라는 이름으로 개발
- 1995년 썬 마이크로시스템스(현 오라클)와의 제휴로 JavaScript로 변경

#### (2) JavaScript 특징
- 인터프리터 언어
- 동적 타이핑 지원
- 객체 기반의 스크립트 언어
- 함수형 프로그래밍 지원
- 프론트엔드 개발, 서버 개발, 데스크탑 개발에 활용

#### (3) ECMAScript
- 1997년 ECMA(European Computer Manufacturers Association)에서 제정한 ECMA-262 기술 표준에 의해 정의된 스크립트 사양
- JavaScript의 표준화를 위해 만들어졌으며, JavaScript는 ECMAScript 사양을 준수하는 범용 스크립트 언어
- **ES6**(ECMAScript 2015): 화살표 함수, 클래스, 모듈, 비동기 처리(Promise, Async/Await) 등 많은 기능 도입
	- (강의 자료에는 "ES6(ECMAScript 2016)"으로 표기되어 있으나, ES6 = ES2015)
- ECMAScript 2024: 최신 버전 (강의 기준)

## 5. 프론트엔드 개발 동향
### 5.1. 프론트엔드 프레임워크
- ==React==: Meta(Facebook)가 개발한 UI 구축용 JavaScript **라이브러리**
	- ==Virtual DOM으로 Real DOM 변경을 최소화==하여 성능 향상
- **Vue**: Evan You가 개발한 점진적(progressive) 프레임워크, Virtual DOM 사용
	- 간결하고 이해하기 쉬워 프로젝트 복잡성 감소
- **Angular**: Google 개발, 엔터프라이즈급, **Incremental DOM** 사용
	- 대규모 애플리케이션의 개발·유지보수에 유리
- **Svelte**: 라이브러리/프레임워크가 아닌 **컴파일러**, Real DOM
- **HTMX**: JS 없이 서버에서 받은 데이터를 HTML 속성만으로 페이지에 동적으로 추가

### 5.2. 프론트엔드 중심 개발 (CSR)
- *프론트엔드 중심 개발*
	- **사용자 인터페이스(UI)가 중심이 되는 개발** 방식이다.
	- 클라이언트가 HTML을 가지고 있거나 서버에서 HTML만 받아오고,
	- 화면 구성에 필요한 **데이터만 JS로 받아와** 데이터와 화면을 조합해 보여준다.
	- 이 방식을 ==CSR(Client-Side Rendering)==이라고 한다.

- **CSR**(Client-Side Rendering)
	- 서버는 데이터만 주고 브라우저가 화면을 구성하는 방식
	- (SPA, PWA 등)

- *프론트엔드 중심 개발의 특징*
	- 사용자 경험(UX), 사용자 인터페이스(UI) 그리고 웹 성능과 웹 접근성이 중요
	- SPA(Single Page App), PWA(Progressive Web App) 등의 구현에 적용 가능
	- 필요한 실시간 데이터만 갱신 가능(REST API) 형태
		- 웹 → 모바일로 이동하면서, 서버로부터 데이터만 수신하고 브라우저에서 화면을 구성하는 CSR 방식으로 개발

- *최근 특징*
	- 인공지능(AI) 기술 연동을 통한 향상된 UX 지원
	- 서버리스 아키텍처(serverless architecture): 클라우드가 인프라 제공
	- JAMstack(JavaScript, APIs, Markup) 아키텍처: SSR 의존성 축소
		- 동적 처리 JavaScript, 정적 콘텐츠, 재사용 가능한 API를 기반으로 웹 구축하는 방식

### 5.3. 모바일 앱 종류
- **네이티브 앱**(Native App)
	- 플랫폼(안드로이드, iOS)에 맞는 언어(Swift, [[03_Kotlin 시작하기|Kotlin]], Java)로 개발, 성능 우수

- **웹 앱**(Web App)
	- 실제로는 웹 방식으로 작동하지만, 사용자에게 앱 같은 경험을 전달

|    구분     |  Native App  |    Web App    |
| :-------: | :----------: | :-----------: |
|   실행 속도   |      빠름      |   일반적으로 느림    |
|    플랫폼    |   플랫폼마다 제작   | 모든 플랫폼에서 실행 가능 |
|    배포     |      앱 마켓     |     배포 불필요     |
|  버전 업데이트  |    시간이 걸림    |     즉시 반영     |
|   오프라인    |     사용 가능     |   일부 기능 사용 가능  |

- **하이브리드 / 크로스 플랫폼 / PWA**
	- 둘의 장점을 결합

## 6. 개발 환경 구축
> 실습 환경을 구축하는 과정이다.

1. **Node.js 설치**
	- 자바스크립트 런타임 환경 (https://nodejs.org/)
	- 설치 후 터미널에서 `node -v`로 버전 확인

2. **VS Code (Visual Studio Code) 설치**
	- Windows, macOS, Linux에서 실행되는 독립 실행형 소스 코드 편집기 (https://code.visualstudio.com/)

3. **VS Code 확장 프로그램 설치**
	- Korean Language Pack for Visual Studio Code (한국어 언어팩)
	- HTML CSS Support (코드 자동 완성)
	- Live Server (서버를 실행하여 개발 내용을 실시간 확인)
	- Code Runner (JavaScript, Java, Python, C++ 코드 실행 및 결과 출력)

4. **프로젝트 실습**
	- 프로젝트 폴더 구성 후 `[Html]` 폴더 내 `hello.html` 파일 생성
	- 기본 HTML 코드 작성 (`<title>`, `<body>` 태그 등)
	- **Live Server**를 통해 브라우저에서 실행 결과 확인
