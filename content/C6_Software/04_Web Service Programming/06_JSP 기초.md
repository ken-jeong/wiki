## 1. 먼저 잡아야 할 핵심
**JSP** (JavaServer Pages)
- HTML 안에 동적인 데이터 표현을 넣어 작성하고, 서버에서 서블릿으로 변환되어 실행되는 기술이다.

이 장에서는 다음 질문에 답할 수 있으면 된다.
1. JSP가 서블릿과 어떤 관계인지 설명할 수 있는가?
2. 변환·컴파일과 요청 처리를 구분할 수 있는가?
3. `page`, `include`, `taglib` 지시어의 용도를 구분할 수 있는가?
4. `<%! %>`, `<%= %>`, `<% %>`를 보고 역할을 판단할 수 있는가?
5. HTML과 자바가 섞인 JSP 예제를 읽을 수 있는가?

권장 학습 순서
- **실행 원리 → 구성요소 → 지시어 → 스크립트 문법 → 예제 → 복습 문제**.

## 2. JSP가 필요한 이유
### 2.1. 서블릿으로 화면을 만드는 불편함
서블릿에서 HTML을 직접 만들면 자바 코드 안에 HTML 문자열을 계속 작성해야 한다.
```java
out.println("<h2>회원 정보</h2>");
```

화면이 복잡해질수록 문자열과 태그를 관리하기 어렵다.
JSP는 HTML을 중심으로 작성하면서 필요한 부분에 데이터나 자바 코드를 넣을 수 있게 한다.
```jsp
<h2><%= member.getUserName() %></h2>
```

**같은 서버 측 기술이지만, JSP는 화면 표현을 작성하기 편하게 만든다.**

cf.
```jsp
<h2>${member.userName}</h2>
```
`member`가 EL에서 접근 가능한 속성으로 저장되어 있다는 전제에서, `${member.userName}`은 해당 객체의 프로퍼티를 읽는 표현이다.
일반적인 JavaBean에서는 `getUserName()`에 대응한다.

### 2.2. JSP의 특징
- HTML 안에 자바 코드와 JSP 전용 문법을 작성할 수 있다.
- Tomcat 같은 **서블릿 컨테이너**가 JSP를 변환하고 실행한다.
- 내장 객체를 이용해 요청, 응답, 세션 등의 정보를 다룬다.
- 커스텀 태그로 반복되는 기능을 태그 형태로 사용할 수 있다.
- EL(Expression Language)로 데이터를 간결하게 표현할 수 있다.

**보충**:
- JSP의 자바 코드는 서버에서 실행된다.
- 브라우저에는 처리 결과인 HTML 등이 전달된다.
- 페이지에 포함된 JavaScript는 브라우저에서 실행될 수 있으므로 JSP의 자바 코드와 구분한다.

### 2.3. 장점과 단점
| 구분  | 핵심 내용                            | 학습 포인트                       |
| --- | -------------------------------- | ---------------------------- |
| 장점  | HTML 중심으로 동적인 화면을 작성하기 쉽다.       | 서블릿의 화면 작성 불편을 줄인다.          |
| 장점  | 커스텀 태그와 태그 라이브러리를 사용할 수 있다.      | 반복되는 표현을 재사용한다.              |
| 장점  | 서블릿 기술과 MVC 구조를 활용할 수 있다.        | 화면과 처리 로직을 나누는 설계에 적용할 수 있다. |
| 단점  | 화면을 수정하면 변환·컴파일 과정이 다시 필요할 수 있다. | JSP 소스가 바로 실행되는 것은 아니다.      |
| 단점  | HTML과 자바를 많이 섞으면 역할 분담이 어려워진다.   | 화면 코드의 가독성이 떨어질 수 있다.        |

## 3. JSP의 동작 과정
### 3.1. 변환부터 응답까지
예를 들어 `hello.jsp`에 요청이 들어오면 다음 과정을 거친다.
1. 컨테이너가 실행에 필요한 변환·컴파일 결과가 있는지 확인한다.
2. 필요하면 JSP를 서블릿 자바 소스로 변환한다. 예: `hello_jsp.java`.
3. 자바 소스를 컴파일하여 `.class` 파일을 만든다.
4. 클래스를 로드하고 서블릿 객체를 생성·초기화한다.
5. `_jspService()`를 통해 요청을 처리한다.
6. 만들어진 HTML 등의 응답을 클라이언트에 전달한다.

**보충**:
- 이미 준비된 서블릿은 이후 요청에도 재사용될 수 있다.
- 따라서 매 요청마다 반드시 JSP 변환과 컴파일을 반복하는 것은 아니다.
- 사전 컴파일도 가능하다.

### 3.2. 생명 주기 메서드
| 메서드             | 호출 시점            | 역할             |
| --------------- | ---------------- | -------------- |
| `jspInit()`     | JSP 서블릿 객체 초기화 시 | 초기화 작업         |
| `_jspService()` | 요청 처리 시          | 요청을 처리하고 응답 생성 |
| `jspDestroy()`  | JSP 서블릿 객체 폐기 시  | 자원 정리          |

**암기**: 초기화 → 요청 처리 반복 → 폐기

## 4. JSP 구성요소
| 구성요소        | 역할                    | 대표 문법·예                     |
| ----------- | --------------------- | --------------------------- |
| **지시어**     | 컨테이너에 페이지 처리 정보를 전달   | `<%@ page ... %>`           |
| 표준 액션       | JSP의 표준 기능 수행         | `jsp:` 접두어의 태그              |
| 템플릿 데이터     | 화면의 기본 내용 구성          | HTML, CSS, JavaScript       |
| **스크립트 요소** | 자바 선언·실행·출력           | `<%! %>`, `<% %>`, `<%= %>` |
| 커스텀 태그      | 개발자나 라이브러리가 정의한 기능 사용 | `<m:printData />`           |
| EL          | 데이터·속성값 표현            | `${member.userName}`        |

## 5. 지시어
> 페이지를 어떻게 처리할지 설정한다.

### 5.1. 기본 형식
```jsp
<%@ 지시어 속성="값" %>
```

세 가지 지시어를 **페이지 설정 / 파일 포함 / 태그 사용 선언**으로 연결해 기억한다.

| 지시어 | 용도 | 대표 속성 |
|---|---|---|
| `page` | 페이지 처리 설정 | `language`, `contentType`, `pageEncoding`, `import`, `errorPage` |
| `include` | 다른 파일의 소스 포함 | `file` |
| `taglib` | 사용할 태그 라이브러리·태그 파일 연결 | `uri` 또는 `tagdir`, `prefix` |

### 5.2. `page`: 페이지 설정
보통 JSP 파일 상단에 작성한다.
```jsp
<%@ page
	language="java"
	contentType="text/html; charset=UTF-8"
	pageEncoding="UTF-8"
	import="java.util.*"
	errorPage="error.jsp" %>
```

| 속성 | 의미 | 예시 해석 |
|---|---|---|
| `language` | 스크립트 언어 지정 | `java`: 자바 사용 |
| `contentType` | 응답의 MIME 형식과 필요 시 문자 인코딩 지정 | `text/html; charset=UTF-8`: UTF-8 HTML 응답 |
| `pageEncoding` | JSP 소스 파일의 문자 인코딩 지정 | 소스를 UTF-8로 해석 |
| `import` | 자바 코드에서 사용할 클래스·패키지 가져오기 | `java.util.*` 사용 |
| `errorPage` | 요청 처리 중 예외가 발생했을 때 사용할 오류 페이지 지정 | `error.jsp`로 오류 처리 |

**자주 헷갈리는 구분**
- `pageEncoding`: **JSP 소스 파일을 읽는 쪽**의 인코딩
- `contentType`의 `charset`: **브라우저에 응답을 보내는 쪽**의 인코딩

**보충**: 위 설정만으로 요청 파라미터의 인코딩까지 모두 설정되는 것은 아니다.

### 5.3. `include`: 다른 파일의 소스 포함
```jsp
<%@ include file="header.jsp" %>
<%@ include file="body.jsp" %>
<%@ include file="footer.jsp" %>
```

`main.jsp`에 위 코드를 작성하면 헤더·본문·푸터의 내용을 합쳐 하나의 화면을 만들 수 있다.

핵심은 **JSP를 자바 소스로 변환할 때 파일 내용을 합친다**는 것이다.
포함된 내용을 함께 처리하여 하나의 서블릿으로 컴파일한다.

- 반복되는 공통 화면을 분리할 수 있다.
- 포함할 파일의 경로는 `file` 속성에 지정한다.
- 조각으로만 사용하는 파일은 완전한 HTML 문서 구조를 갖출 필요가 없다.
- 포함할 위치에 지시어를 작성한다.

**보충**:
- `file="header.jsp"`는 현재 JSP 기준의 상대 경로다.
- `/`로 시작하는 경로는 웹 애플리케이션 루트 기준이며, 운영체제 파일시스템의 루트와 구분한다.

**보충**:
- `<%@ include ... %>`는 번역 시 소스를 포함하는 지시어다.
- 요청 처리 시 다른 자원의 실행 결과를 포함하는 표준 액션 `<jsp:include ... />`와 구분한다.
- [공식 JSP 명세의 include 설명](https://jakarta.ee/specifications/pages/3.0/jakarta-server-pages-spec-3.0.html#the-include-directive)

### 5.4. `taglib`: 태그 사용을 위한 연결
태그 라이브러리를 사용할 때:
```jsp
<%@ taglib
	uri="태그라이브러리식별자"
	prefix="접두어" %>
```

태그 파일을 사용할 때:
```jsp
<%@ taglib
	tagdir="/WEB-INF/tags"
	prefix="m" %>

<h2><m:printData /></h2>
```

위 예제는 `/WEB-INF/tags/printData.tag`에 구현된 기능을 `m:printData`라는 태그로 사용하는 형태다.

| 속성 | 역할 |
|---|---|
| `uri` | 사용할 태그 라이브러리를 식별 |
| `tagdir` | 태그 파일이 있는 디렉터리 지정 |
| `prefix` | 페이지에서 태그를 부를 때 사용할 접두어 지정 |

- TLD(Tag Library Descriptor)는 태그 라이브러리의 태그·설정 등을 기술하는 파일이다.
- JSTL은 표준 태그 라이브러리이며, 개발자가 직접 구현한 태그와 구분한다.
- **기억법**: `prefix:태그명`

## 6. 템플릿 데이터와 EL
### 6.1. 템플릿 데이터
**템플릿 데이터**
- 화면의 기본 내용을 이루는 부분이다.

JSP에서도 일반 HTML처럼 다음을 사용할 수 있다.
- HTML: 문서 구조와 화면 요소.
- CSS: 스타일과 배치.
- JavaScript: 브라우저에서의 동작.
- Bootstrap: 화면 스타일링을 돕는 라이브러리.
- Axios: HTTP 통신에 사용하는 Promise 기반 JavaScript 라이브러리.

강의에서 제시한 방향은 **HTML로 구조를 만들고, JSTL과 EL로 데이터를 표현하는 것**이다.

### 6.2. EL: 속성값을 간단히 표현
```jsp
<p>이름: ${member.userName}</p>
<p>이메일: ${member.email}</p>
```

`member`라는 이름으로 사용할 수 있는 객체의 속성을 읽어 화면에 표현한다.

**보충**:
- 일반적인 자바빈이라면 `${member.userName}`은 `getUserName()`과 같은 getter를 통해 속성을 읽는다.
- 객체를 요청 등의 범위에 속성으로 제공했다는 전제가 필요하다.
- 스크립틀릿의 지역변수가 자동으로 EL 변수로 등록되는 것은 아니다.

다음 두 표현은 `member`가 각각 올바르게 제공되었다는 전제에서 같은 속성값을 표현하는 예다.

```jsp
<%= member.getUserName() %>
${member.userName}
```

**주의**:
- EL은 데이터 표현을 간단하게 하는 문법이다.
- 모든 자바 실행 코드를 그대로 옮겨 적는 문법으로 이해하지 않는다.

## 7. 스크립트 요소
| 이름    | 문법           | 하는 일         | 서블릿 변환 후 위치·의미     |
| ----- | ------------ | ------------ | ------------------ |
| **선언**    | `<%! ... %>` | 멤버 변수·메서드 선언 | 서블릿 클래스의 멤버        |
| **표현식**   | `<%= ... %>` | 표현식의 결과 출력   | 요청 처리 중 출력         |
| **스크립틀릿** | `<% ... %>`  | 자바 문장 실행     | `_jspService()` 내부 |

**암기**: `!`는 선언, `=`는 출력, 나머지는 실행

### 7.1. 선언: `<%! ... %>`
```jsp
<%!
	int one;
	int two = 1;
	
	public int plusMethod() {
		return one + two;
	}
%>
```

- `one`, `two`는 멤버 변수다.
- `plusMethod()`는 멤버 메서드다.
- 인스턴스 변수 `one`은 기본값 `0`이므로 위 상태에서 메서드의 반환값은 `1`이다.

**보충**:
- 선언한 멤버 변수는 같은 서블릿 객체의 여러 요청에서 공유될 수 있다.
- 사용자별 요청 데이터를 저장하는 용도로 생각하면 안 된다.

### 7.2. 표현식: `<%= ... %>`
```jsp
<p>합계: <%= 10 + 20 %></p>
<p>현재 시간: <%= java.time.LocalDateTime.now() %></p>
```

결과값을 응답에 출력한다. 위 첫 번째 예제는 `<p>합계: 30</p>`을 만든다.

- 변수값, 연산 결과, 메서드 반환값 등을 출력한다.
- **표현식 끝에 세미콜론을 붙이지 않는다.**
- 선언문이나 일반 실행문을 넣는 자리가 아니다.

```jsp
<%= 10 + 20 %>
```

위는 올바른 예다. 다음은 잘못된 예다.

```jsp
<%= 10 + 20; %>
```

> 여러 줄에 걸쳐 작성할 수 있지만, 내용은 유효한 자바 표현식이어야 한다.

### 7.3. 스크립틀릿: `<% ... %>`
```jsp
<%
    int sum = 10 + 20;
%>
<p>합계: <%= sum %></p>
```

스크립틀릿은 계산하고, 표현식은 그 결과를 출력한다.

- 지역변수 선언, 조건문, 반복문 등을 작성한다.
- 자바 문장에는 필요한 세미콜론을 붙인다.
- `_jspService()` 안에 들어가는 코드이므로 그 위치에서 허용되는 자바 문법을 사용한다.
- HTML과 스크립틀릿을 번갈아 작성할 수 있다.

**보충**:
- JSP의 HTML 부분도 변환된 서블릿에서는 `out.write(...)` 같은 출력 코드로 처리된다.
- [공식 JSP 명세의 템플릿·스크립트 설명](https://jakarta.ee/specifications/pages/3.0/jakarta-server-pages-spec-3.0.html)

### 7.4. 강의에 등장하는 내장 객체
| 객체            | 용도                           |
| ------------- | ---------------------------- |
| `request`     | 클라이언트의 요청 정보와 파라미터 접근        |
| `response`    | 클라이언트로 보낼 응답 제어              |
| `out`         | 응답 내용 출력                     |
| `session`     | 세션에 데이터 저장·조회                |
| `application` | 웹 애플리케이션 범위의 데이터·정보 접근       |
| `pageContext` | JSP 페이지의 실행 문맥과 여러 범위의 속성 접근 |
| `config`      | 서블릿 설정 정보 접근                 |

이 표는 강의에서 열거한 객체의 역할을 풀어 쓴 것이다.
내장 객체 전체를 모두 열거한 표는 아니다.

## 8. 강의 예제 읽기
### cf. 주석
```jsp
<!-- HTML 주석: 화면에는 안 보이지만 브라우저 소스에는 남는다. -->
<%-- JSP 주석: 변환 단계에서 제거되어 브라우저 소스에도 남지 않는다. --%>
```

### 8.1. 요청 파라미터를 가져와 출력
요청 예: `hello.jsp?uname=Kim`

```jsp
<%
    String name = request.getParameter("uname");
%>
<h2><%= name %></h2>
```

1. `"uname"`은 요청에 포함된 **파라미터 이름**이다.
2. `name`은 값을 저장하는 **자바 지역변수**다.
3. `request.getParameter("uname")`은 `"Kim"`을 가져온다.
4. `<%= name %>`이 값을 응답에 출력한다.

**보충**:
- `getParameter()`는 URL의 쿼리 문자열뿐 아니라 파라미터로 처리되는 폼 데이터에도 사용한다.
- 해당 파라미터가 없으면 `null`을 반환한다.
- 위 코드는 문법 학습용이며 출력값의 HTML 이스케이프 처리는 생략했다.

### 8.2. 반복문과 HTML을 섞어 표 출력
전제: 앞선 자바 코드에서 `mlist`와 `Member`를 사용할 수 있고, 강의 예제처럼 `m.name`, `m.email` 필드에 접근할 수 있다고 가정한다.

```jsp
<table>
<% for (Member m : mlist) { %>
    <tr>
        <td><%= m.name %></td>
        <td><%= m.email %></td>
    </tr>
<% } %>
</table>
```

| 부분 | 의미 |
|---|---|
| `<% for (...) { %>` | 회원 목록 반복 시작 |
| `<tr>` | 표의 행 생성 |
| `<td>` | 표의 데이터 셀 생성 |
| `<%= m.name %>` | 현재 회원의 이름 출력 |
| `<%= m.email %>` | 현재 회원의 이메일 출력 |
| `<% } %>` | 반복문 종료 |

회원이 3명이면 `<tr>...</tr>`이 3번 생성된다.
JSP 태그가 중간에 닫혀도 자바 반복문의 `{ ... }` 범위는 계속 이어진다.

강의에서는 같은 출력을 `out.println()`으로 만드는 방식도 소개한다.

```jsp
<table>
<%
    for (Member m : mlist) {
        out.println("<tr><td>" + m.name
            + "</td><td>" + m.email + "</td></tr>");
    }
%>
</table>
```

두 방식은 같은 형태의 HTML을 만들 수 있다.
첫 번째 방식은 HTML 구조가 직접 보여 화면 코드를 읽기 쉽다.
